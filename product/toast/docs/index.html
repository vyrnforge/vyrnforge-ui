Toast provides a polite notification viewport and dismissible notification anatomy without owning application messaging queues, severity policy, persistence, or domain events.

Overview

Use Toast for transient, non-blocking status messages. Routine notifications use polite status semantics and do not move focus automatically.

Installation and imports

Import from each framework's /toast subpath and load @vyrnforge/web/styles/toast.css. Elements registers vf-toast and vf-toast-viewport explicitly; importing the module does not register them globally.

Quick start

Anatomy

Viewport, root, title, description, and an optional native-button close control. The close control has no library-authored English label; provide visible button text or an authored aria-label/aria-labelledby when the control is icon-only.

State ownership

open is externally meaningful state. When supplied, it is authoritative: close and timeout interactions request false, but the Toast stays visible until the owner commits the closed state. When open is absent, the port owns local state initialized once from defaultOpen, which defaults to true. Later default changes do not reset live uncontrolled state.

Duration and pause behavior

The default duration is 5000 ms. duration=0 is persistent. Only a finite positive duration arms a timer; negative or non-finite runtime values behave persistently. A changed positive duration restarts the current open cycle with that duration, while ordinary rerenders or callback identity changes do not reset the deadline.

Finite timers pause while pointer hover or keyboard focus is inside the Toast. Hover and focus are independent pause reasons, so timing resumes only after both have cleared. A duration change while paused replaces the remaining duration but remains paused. Closing, unmounting, or disconnecting clears the old timer; a real close followed by reopen starts a fresh full duration. Timers start only after client activation.

Close behavior

Close remains a native button and uses native Enter/Space activation. One activation requests one close transition. A supported consumer click handler may cancel the request with preventDefault(). Vue retains its dismiss notification for compatibility while root state changes through the root open-change contract.

Elements migration

New timed or controlled Elements usage should register and use vf-toast as the state-owning root. The existing vf-toast-viewport registration signature remains supported. Legacy authored [data-vf-toast-root] content inside the viewport keeps uncontrolled close behavior without DOM deletion; migrate it to vf-toast when controlled state, timeout, or pause behavior is required.

Accessibility

The viewport uses polite live-region semantics and each Toast root uses status semantics by default. Consumers own meaningful notification content and close-control names. DOM and automated accessibility assertions verify semantic wiring; they do not establish that a particular screen reader spoke a particular message. Manual assistive-technology evidence remains a separate review boundary.

Timing responsibility

A five-second default is component policy, not permission to remove the only access to essential information or an action. Use a persistent Toast or provide equivalent durable access when the notification contains information or an action that would otherwise disappear before the user can use it.

Consumer boundary

The application owns queueing, message text, translation, severity policy, persistence/history, business actions, retries, and domain-event handling. Toast does not introduce an application notification service or global state runtime.

Forms

Toast is not form-associated.

Styling

Canonical CSS is Web-owned and token driven.

Framework API

React exposes open, defaultOpen, duration, and onOpenChange. Angular exposes open, defaultOpen, duration, and openChange through directives. Vue exposes open, defaultOpen, duration, update:open, and openChange, while retaining dismiss on the close control for compatibility. Elements exposes VfToastElement/defineToastElement, the open, defaultOpen, and duration properties, and vf-open-change; defineToastViewportElement keeps its existing signature.

CSR and SSR

React, Angular, and Vue imports and semantic server rendering are server safe. Browser timers and interaction listeners begin only after activation. Elements uses explicit upgrade/connection/disconnection behavior rather than a framework SSR contract.

Testing guidance

Test controlled acceptance/rejection, uncontrolled close, close/reopen timing, duration changes, rerender stability, rejected timeout intent, overlapping hover/focus pause, click cancellation, ownership isolation, localized naming, live-region semantics, teardown, SSR/activation, public types, and package entrypoints.

Compatibility

React, Angular, Vue, and Elements implement the same state, timing, close, and naming semantics through idiomatic APIs. Observable behavior is shared; lifecycle and state execution remain port-local.
