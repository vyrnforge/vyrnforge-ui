Dialog presents focused modal content with native dialog semantics and documented open, dismissal, and focus behavior.

Overview

Use Dialog for modal tasks that temporarily require attention or a decision. Use a non-modal surface such as Popover for contextual content that should not block interaction with the rest of the page.

Anatomy

A Dialog contains a dialog root, authored title, optional description, body content, and consumer-authored controls. Use the documented title and description parts to establish accessible relationships.

Variants and sizes

Dialog has no semantic variant or size enum in this channel. Adjust layout through documented styling hooks and application CSS without changing modal semantics.

State

React supports controlled open or uncontrolled defaultOpen; Vue uses modelValue with optional defaultOpen; Angular supports open with optional defaultOpen. Controlled usage requires the application to commit requested state changes.

Behavior

Opening activates modal dialog behavior in the browser. Escape, optional backdrop activation, and close controls can request dismissal with reason escape, backdrop, or close-control. Preventing a documented dismissal request keeps the dialog open.

Interaction

Escape requests dismissal. Backdrop dismissal is opt-in. Interacting with dialog content does not count as backdrop activation, and close controls request dismissal explicitly.

Accessibility

Provide meaningful title text and, when useful, a description. An initial-focus target is optional. When the dialog closes, focus returns to the previous meaningful target when that target remains available.

Forms

Forms may be composed inside Dialog. Submission, validation, confirmation, and reset behavior remain application concerns and follow the contracts of the controls used inside the dialog.

Styling

Stable hooks are data-vf-dialog-root, data-vf-dialog-title, data-vf-dialog-description, data-vf-dialog-body, and data-vf-dialog-close, with data-vf-open and data-vf-backdrop-dismiss for documented state and policy. Use ::backdrop for backdrop styling.

CSR and SSR

Server output preserves the dialog content and accessible relationships. Browser modal activation and focus behavior begin on the client. Follow the controlled-state API during hydration so application state remains authoritative.

Examples

The Quick start example demonstrates title and description relationships, close controls, optional backdrop dismissal, and the supported React, Angular, and Vue APIs.

Do / Don't

Do use Dialog for genuinely modal tasks, provide a meaningful title, and choose dismissal policy deliberately. Don't use Dialog for lightweight contextual content or hide essential close/confirmation actions.

Testing guidance

Test opening and closing, Escape behavior, optional backdrop dismissal, close controls, focus movement and restoration, controlled-state callbacks, hydration, and accessibility through observable browser behavior.

Compatibility

Dialog is documented for React, Angular, and Vue in this channel. An Elements-specific Dialog entrypoint is not currently available. See the Compatibility reference for supported runtime and browser ranges.
