Radio is one native radio input, not a collection manager.

Overview

Use Radio for an individual input[type=radio]. Native name grouping and form behavior remain browser-owned.

Installation and imports

Load @vyrnforge/web/styles/radio.css. React, Angular, and Vue use their /radio entrypoints; Native Web uses data-vf-radio.

Quick start

Platform-adaptable workflow

The STD-25 example stages one delivery-speed choice and commits it through an explicit confirmation action while keeping the semantic values stable across current Web surfaces.

Native Android, Apple-platform, and desktop products should preserve the same task meaning while using their platform-appropriate selection and command surfaces. Those mappings are guidance only: VyrnForge does not currently provide native Android, iOS, macOS, Windows, or Linux renderers. An Elements-specific Radio wrapper is not fabricated where native HTML already supplies the required control semantics.

Accessibility

Provide an accessible label and preserve native grouping, keyboard, checked, disabled, and form semantics.

Styling

Canonical radio styling lives in the Web package and is token-driven. Preserve the native radio element so grouping, focus, and assistive-technology semantics remain browser-owned.

Framework API

React and Vue expose Radio; Angular decorates input[vfRadio]. Grouping continues to use the native name contract rather than a Layer 2 collection abstraction.

Compatibility

Radio relies on standard native radio behavior across modern browsers. Visual rendering may differ slightly by platform while grouping and form semantics remain consistent. Platform-adaptation examples demonstrate current Web implementation only and do not imply native-platform renderer support.

Layer boundary

Managed RadioGroup focus and collection coordination belong above Layer 2.
