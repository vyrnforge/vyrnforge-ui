Surface is a non-interactive visual boundary for themed content containment.

Overview

Use Surface when content needs the shared VyrnForge background, foreground, border, and radius treatment. Layout remains the responsibility of layout primitives or ordinary CSS.

Installation and imports

Native Web uses @vyrnforge/web/styles/surface.css. Framework entrypoints are @vyrnforge/react/surface, @vyrnforge/angular/surface, @vyrnforge/vue/surface, and @vyrnforge/elements/surface.

Quick start

Anatomy

Surface has one visual root and preserves authored content.

Variants and sizes

There are no variants or size props in the initial contract.

State

Surface has no component state.

Behavior

Surface applies visual containment only.

Interaction

Surface adds no keyboard, focus, or pointer behavior.

Accessibility

Surface adds no role or ARIA semantics. Choose the semantic element required by the content.

Forms

Surface does not participate in form state or submission.

Styling

The stable Native Web hook is data-vf-surface. Paint uses semantic color tokens and --vf-radius-surface. Surface intentionally adds no padding.

Framework API

React and Vue expose Surface with as; Angular exposes vfSurface; Elements exposes vf-surface; Native Web uses the data hook.

CSR and SSR

Native Web needs no hydration. React, Angular, and Vue preserve the shared hook during SSR. Elements registration is explicit and server-safe to import.

Examples

The basic example shows the same visual contract on all five surfaces.

Do / Don't

Do compose Surface with layout primitives when spacing is needed. Don't treat Surface as a generic style-prop Box.

Testing guidance

Test the stable hook, semantic root, token-driven paint, and absence of interaction or implicit spacing.

Compatibility

Surface is defined for Native Web, React, Angular, Vue, and Elements in the rebuild channel.
