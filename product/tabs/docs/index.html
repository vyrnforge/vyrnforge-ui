Tabs presents one active panel from a labeled set with documented selection, keyboard navigation, focus, and accessibility behavior.

Overview

Use Tabs when several peer sections share one region and users should switch between them without navigating to another location. A Tabs instance contains a root, tablist, tabs, and corresponding tabpanels.

Anatomy

A Tabs instance contains one root, one tablist, one or more tabs, and one corresponding tabpanel per tab. Tabs and panels are connected through their documented values and accessible relationships.

Variants and sizes

Tabs has no size variants in this channel. Configure behavior with orientation and activation mode.

State

Selection and keyboard focus are distinct. The selected tab exposes aria-selected="true"; disabled tabs expose aria-disabled="true" and are skipped during keyboard movement. Inactive panels are hidden.

Behavior

Automatic activation selects a tab when keyboard focus moves to it. Manual activation keeps focus and selection separate until Enter or Space is pressed. Pointer activation selects an enabled tab in either mode.

Interaction

Horizontal tablists use Left and Right Arrow; vertical tablists use Up and Down Arrow. Home moves to the first enabled tab and End to the last. Navigation wraps and skips disabled tabs. Horizontal arrow mapping follows text direction.

Accessibility

Give every tablist an accessible name with aria-label or aria-labelledby. Every tab must identify its panel and every panel must identify its tab. Keep focus indication visually distinct from selected styling.

Forms

Tabs does not define form values, validation, submission, or reset behavior. Place form controls inside tabpanels according to the controls' own documentation.

Styling

Stable hooks are data-vf-tabs-root, data-vf-tabs-list, data-vf-tabs-tab, and data-vf-tabs-panel, along with documented state hooks for selection, disabled state, orientation, and activation. Prefer public --vf-* tokens and stable hooks for customization.

ElementsRegister <vf-tabs> with defineTabsElement(). Use value for controlled state, default-value for initial uncontrolled state, and listen for vf-value-change.

CSR and SSR

React, Angular, and Vue can render tab roles, selection, panel visibility, and relationships during SSR. Elements becomes interactive after registration and browser upgrade. Follow the component API for controlled state during hydration.

Examples

The Quick start example demonstrates three tabs, a disabled tab, and the supported React, Angular, Vue, and Elements APIs.

Do / Don't

Do use Tabs for peer sections, provide an accessible tablist name, and keep tab labels concise. Don't use Tabs as application routing or recreate its keyboard behavior with application-specific handlers.

Testing guidance

Query by role and accessible name, assert selected state and visible panel outcomes, and test keyboard movement, disabled skipping, wrapping, Home/End, activation mode, orientation, directionality, and browser focus.

Compatibility

Tabs is documented for React, Angular, Vue, and Elements in this channel. See the Compatibility reference for supported runtime and browser ranges.
