Portal / RenderHost is Layer 4 infrastructure for rendering authored content into an explicit alternate host without taking ownership of overlay behavior.

Overview

Use Portal when a later component must render content outside its normal DOM position while preserving the framework's authored subtree and context.

Installation and imports

Framework entrypoints are @vyrnforge/react/portal, @vyrnforge/angular/portal, @vyrnforge/vue/portal, and @vyrnforge/elements/portal.

Quick start

Anatomy

Portal has authored content and one explicit target/render host. It adds no visible wrapper contract.

Variants and sizes

Portal has no visual variants or sizes.

State

Portal owns no open/closed or overlay state. Consumers control whether content is authored and where it renders.

Behavior

React uses createPortal, Vue uses Teleport, Angular moves an embedded view to the supplied target, and Elements moves its authored child nodes to the target.

Interaction

Portal adds no keyboard, pointer, focus, dismissal, or positioning behavior.

Accessibility

Moving content does not change its semantic responsibility. The consuming composite remains responsible for relationships, focus order, labels, and modal semantics.

Forms

Portal does not own form state. Consumers must account for native DOM form-owner behavior when moving native form controls.

Styling

Portal has no canonical CSS. Styling belongs to the rendered content and consuming component.

Framework API

React exposes Portal with target and disabled; Angular exposes vfPortal on an ng-template; Vue exposes Portal backed by Teleport; Elements exposes vf-portal with a target selector or targetElement.

CSR and SSR

Imports are server-safe. React and Angular retain content inline when no live target exists; Vue supports disabled inline rendering during SSR. Portal activation must not assume browser globals at module evaluation.

Examples

The basic example renders one button into a separate host in each framework port.

Do / Don't

Do use Portal as a rendering primitive for later overlays. Don't put focus management, dismissal, positioning, or application state into Portal.

Testing guidance

Test target placement, cleanup, SSR fallback, context preservation where relevant, and accessibility of the consuming composition.

Compatibility

Portal is a Layer 4 port primitive for React, Angular, Vue, and Elements. There is no Native Web wrapper because native DOM authors already choose a render host directly.
