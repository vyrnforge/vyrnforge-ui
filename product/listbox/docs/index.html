Listbox presents a keyboard-navigable set of options with single or multiple selection.

Overview

Use Listbox when options remain visible rather than opening from a trigger.

Installation and imports

Import from the framework-specific /listbox subpath and load @vyrnforge/web/styles/listbox.css.

Quick start

Anatomy

Root and Option form the public composition; consumers author stable values, option text, accessible naming, and disabled state.

State

Supports single or multiple selected values with framework-idiomatic controlled or uncontrolled ownership where available. Selection is persistent semantic state and remains distinct from keyboard focus.

Behavior

After client activation, enabled options use roving tabindex so the Listbox contributes one Tab stop. If focus is outside, the first selected enabled option is the preferred entry point; otherwise the first enabled option is used. Focus movement does not implicitly change selection.

Interaction

Up/Down Arrow move focus among enabled options, Home/End move to the first or last enabled option, and typeahead moves focus by option text. Enter or Space changes selection on the focused option. In multiple mode, selection toggles without clearing other selected options.

Accessibility

The root uses role="listbox", options use role="option" with aria-selected, and multiple mode exposes aria-multiselectable="true". Consumers provide the Listbox's meaningful accessible name with aria-label or aria-labelledby. Options should contain selectable option content rather than nested interactive controls.

Forms

Listbox is not inherently form-associated; consumers own serialization, validation, submission, and application-level required/error policy.

Styling

Canonical CSS is Web-owned, token driven, and must keep focus visually distinct from selected state.

Framework API

React and Vue expose components, Angular exposes standalone directives, and Elements exposes explicit registration for the same conceptual contract. Elements supports selection-mode="multiple" for the shared multiple-selection model.

CSR and SSR

Imports are server safe. Server-rendered framework options remain ordinarily focusable before client activation; the client establishes the single roving Tab stop when composite keyboard behavior becomes active.

Do / Don't

Do use Listbox for visible selectable options with concise accessible names. Don't put links, buttons, or other independently interactive controls inside an option; use a different composite such as Grid when option contents need independent interaction.

Testing guidance

Test single and multiple selection, one-Tab-stop behavior, focus-versus-selection separation, Up/Down, Home/End, typeahead, disabled options, controlled/uncontrolled state where applicable, SSR-safe imports, and automated accessibility guardrails.

Compatibility

React, Angular, Vue, and Elements implement sibling Listbox ports using shared lower-layer navigation, focus, selection, and typeahead capabilities.
