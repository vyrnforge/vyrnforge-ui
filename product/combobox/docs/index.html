Combobox combines an editable text field with a filtered listbox while keeping selection, navigation, and application data responsibilities explicit.

Overview

Use Combobox when users benefit from typing to narrow an authored set of available options. The component composes accepted collection-navigation, selection, floating-surface, and native input semantics instead of introducing a separate interaction runtime.

Installation and imports

Import Combobox from the framework-specific /combobox subpath and load @vyrnforge/web/styles/combobox.css. Canonical styling remains owned by @vyrnforge/web.

Quick start

Anatomy

Root, editable input, popup content, and options form the public composition. Consumers provide option values, display text, labels, and surrounding field relationships.

State

Open state, input text, committed value, and the currently active suggestion are distinct concerns. Controlled or uncontrolled value state remains framework-idiomatic where the port supports both; product data fetching and persistence remain outside the component.

Behavior

Typing filters authored options. Down Arrow and Up Arrow move the active enabled visible suggestion without moving DOM focus away from the input. Enter commits the active option, and Escape dismisses the popup. Active options are scrolled into view as navigation changes aria-activedescendant.

Interaction

The editable control remains a native text input and the popup options are excluded from the page Tab sequence. Combobox does not capture Home, End, printable characters, or other standard text-editing keys. Pointer selection returns focus to the input after the value is committed.

Accessibility

The input exposes role="combobox", aria-autocomplete="list", popup state, aria-controls, and aria-activedescendant while a suggestion is active. The popup uses listbox semantics; options expose selection and disabled state. This follows the adopted editable Combobox/listbox active-descendant model while consumers remain responsible for an accessible input name, validation descriptions, and meaningful option content.

Forms

Combobox does not invent form submission or validation policy. Consumers own form names, required state, validation messaging, serialization, and server-side interpretation of the selected value.

Styling

Canonical CSS is Web-owned, token-driven, and shared across ports. Product-specific option rendering and application layout should compose around the public anatomy rather than override interaction behavior.

Framework API

React and Vue expose idiomatic components, Angular exposes standalone directives, and Elements exposes an explicit-registration custom element. All ports implement the same conceptual input/listbox relationship without making one framework the source of truth.

CSR and SSR

Package imports are server safe. The rendered input/listbox relationship remains semantic before activation; browser-only positioning, active-descendant navigation, focus restoration, and dismissal behavior start after the rendered elements are available.

Do / Don't

Do use Combobox for editable selection from known options. Don't make the library own remote search services, application routing, permissions, domain-specific result rendering, or a global localization runtime.

Testing guidance

Test filtering, input-retained DOM focus, aria-activedescendant movement, disabled-option skipping, option Tab exclusion, Enter selection, Escape dismissal, active-option visibility, declared-locale filtering where the component owns it, IME composition boundaries, LTR/RTL layout, SSR-safe imports, and automated accessibility checks. Targeted assistive-technology, IME, language, and browser evidence remains required for release-level support claims.

Compatibility

React, Angular, Vue, and Elements provide sibling implementations of the shared Combobox concept, with Web-owned canonical CSS and lower-layer collection navigation reused where applicable.
