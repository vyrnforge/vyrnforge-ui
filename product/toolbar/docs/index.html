Toolbar groups related controls and links into one keyboard-navigable command surface.

Overview

Use Toolbar for a compact set of peer actions whose grouping improves navigation and comprehension.

Installation and imports

Import from the framework-specific /toolbar subpath and load @vyrnforge/web/styles/toolbar.css.

Quick start

Anatomy

Root, Button, Link, and Separator form the public composition.

State

Toolbar itself owns no command state; child controls retain their own pressed, disabled, or navigation state. After client activation, one enabled item is the toolbar's sequential Tab stop and the last-focused enabled item is retained for re-entry.

Behavior

The root coordinates roving focus among enabled peer items without changing their native activation behavior. Disabled and aria-disabled items are skipped by directional navigation.

Interaction

Horizontal toolbars use Left/Right Arrow, respecting LTR/RTL direction; vertical toolbars use Up/Down Arrow. Home/End move to the first or last enabled item. Tab and Shift+Tab enter or leave the toolbar once rather than visiting every child.

Accessibility

The root exposes toolbar semantics and an authored accessible name while children retain native button/link roles and disabled semantics. The enhanced interaction follows the WAI-ARIA APG Toolbar pattern's roving-focus model; VyrnForge owns focus eligibility and navigation while consumers own meaningful labels and command behavior.

Forms

Toolbar does not own form state; button children default to non-submitting behavior unless explicitly composed otherwise.

Styling

Canonical CSS is Web-owned, token-driven, and preserves visible focus and forced-colors behavior.

Framework API

Ports expose the same orientation and child-item contract idiomatically; no accessibility-profile prop is required for the standard Toolbar behavior.

CSR and SSR

Imports are server safe. Server markup remains ordinary usable controls before client activation; the client establishes and maintains the single roving Tab stop when the Toolbar becomes interactive.

Do / Don't

Do use for related peer controls. Don't put routing, command dispatch, permissions, or global shortcut management inside VyrnForge.

Testing guidance

Test the single Tab stop, horizontal LTR/RTL and vertical navigation, Home/End, disabled-item skipping, dynamic availability, native child activation, SSR/hydration, and accessibility scanning against real framework ports.

Compatibility

React, Angular, Vue, and Elements implement sibling Toolbar ports with the same observable roving-focus contract.
