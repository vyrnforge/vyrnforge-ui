# L5 Popover native migration

Related: #1287, #1280.

- Native auto popover owns top layer, light-dismiss, nested Escape and browser focus restoration. CSS anchor positioning owns placement/fallback. No generic runtime or portal required.
- Root owns content ID and role (dialog or region); consumers author a meaningful accessible name and content. Keep content mounted while closed to preserve SSR relationships.
- React/Vue: move authored content ID and role to Root via contentId/contentRole; remove portal option. Angular requires a stable root ID and uses the same root-owned content contract. Elements retains authored content ID/role or generates a unique ID.
- Controlled owners receive native visibility requests. A rejected close reconciles to the committed value; native auto popover peer exclusivity still applies, so consumers must not command incompatible simultaneously open peers. Nested popovers are supported by browser top-layer behavior.
- Cross-engine, RTL, placement/reflow, packed/API and manual evidence remain required. No broad conformance or release claim.

The native platform does not reliably return focus from nested popovers. Runtime ports record whether focus was inside immediately before dismissal and restore the trigger only if focus would otherwise be lost; outside focus is preserved. The Web baseline remains declarative native behavior.
