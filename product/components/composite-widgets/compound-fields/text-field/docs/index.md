# TextField

TextField composes a visible label, one native input or textarea, optional adornments and accessible description/error relationships. It does not own a form store or business validation.

## When to use

Start with TextField for ordinary labeled forms. Input and Textarea are lower-level native editing primitives for custom compositions or native modes, not competing full-field APIs. Use existing SearchField, PasswordField and NumberField when their specialized query, visibility or stepping behavior is required. Native temporal and color modes remain Input.

## Appearance and typography

Outlined is the default; filled uses a clearly tinted theme-derived surface with rounded top corners and bottom rule, while underlined uses a transparent surface, minimal horizontal inset, square corners and bottom rule. Label placement is independent of appearance: outside (default) or floating. The real label moves from the editor to the notch on outlined fields, or to the upper interior on filled/underlined fields. Empty unfocused single-line text editors rest; focus, content, and native autofill raise the label. Number, multiline and adorned fields keep the label raised to avoid collision. A real placeholder is optional and visible when the label is raised. For long or translated labels prefer outside placement, which wraps naturally. Floating labels are visually clipped when space is limited; their accessible names remain complete. Omitted field size follows inherited density; explicit sm, md and lg select shared control geometry. Native input size, textarea rows and cols remain native. Full width is optional. Logical start/end alignment supports RTL. Leading/trailing slots accept authored artwork or actions; prefix/suffix are visible text. Meaningful units must also be named in label or description. Actions must use accessible names, type=button, and consumer-managed disabled/read-only policy.

Typography uses the shared font family, size, weight and line-height roles. The existing theme authoring function accepts component-specific CSS font shorthand and letter-spacing tokens for value, placeholder, label, message and affix. The placeholder inherits value typography by default. Also supported: --vf-text-field-radius, --vf-text-field-background and --vf-text-field-border-color. These optional overrides inherit through theme scopes; absent values resolve at the consuming CSS declaration to shared semantic defaults. No component theme runtime is required. Verify custom contrast and readable geometry.

## Native behavior and validation

Native value, defaultValue, change events, focus, selection, composition, paste, autocomplete, input mode, required, disabled, readonly, form association, reset and submission are preserved. Controlled values and reset are consumer-owned. Native invalid presentation uses user-invalid; authored error text marks aria-invalid and is appended to aria-describedby without dropping external descriptions. Warning/success are presentation only; author meaningful text and do not rely on color. No automatic live announcements or focus movement. Requiredness conventions are localized and authored in the label or form instructions.

Multiline uses a native textarea, preserving rows and columns; autosize delegates to Textarea, with CSS field-sizing where supported and native resize and rows as fallback. In React, autosize alone selects the multiline primitive at initial render. Explicit multiline without autosize remains the fixed-height mode. Input-only type and explicit multiline=false are incompatible with autosize. Changing the mode is an explicit element replacement, never triggered by editing content. Standalone and composed editors share appearance, border geometry, typography, states and density; the surrounding label/adornments remain TextField responsibilities. Character limits use native maxlength; a visible counter can be consumer-authored as description. Use tolerant native text entry and explicit parsing at a suitable boundary for currency, percentage and masks; never silently rewrite editing text or composition.

## Native Web

Load `@vyrnforge/web/styles/text-field.css`. Author the same hooks on a div root, label, control wrapper (data-vf-text-field-control and data-vf-editor-surface), real input (data-vf-input and data-vf-text-field-value) or textarea (data-vf-textarea and data-vf-text-field-value), and data-vf-editor-variant="unstyled" on the editor, and optional described text. Author unique IDs, label for, aria-describedby and aria-invalid. For floating placement put the real label inside the control wrapper, set data-vf-text-field-label-placement=\"floating\" on the root, and add a decorative aria-hidden fieldset with data-vf-text-field-outline and legend/span duplicating the label text for the outlined variant. Use a space placeholder when no authored hint exists, and data-vf-text-field-always-raised for multiline, number and adorned fields. No controller is required. React-first evidence does not establish other framework adapter support.
