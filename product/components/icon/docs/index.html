Icon renders non-interactive SVG artwork with consistent size, color, variant, shape, and accessibility behavior.

Overview

Use Icon for symbolic visual content. Keep actions and navigation on semantic controls such as Button or Link. Official VyrnForge artwork is available from @vyrnforge/icons.

Quick start

The example uses the Bookmark icon and runs in the framework selected in the documentation shell.

Anatomy

Icon renders SVG artwork from an IconDefinition. Treat the definition as the public artwork input; SVG path details are not a composition surface.

Variants and sizes

variant is outlined or filled. shape is rounded or sharp. Sizes are sm, md, and lg; outlined + rounded and md are the defaults.

State

Icon has no selected, disabled, invalid, busy, or pressed state of its own. Those states belong to the component or application concept that owns the icon.

Behavior

Icon renders the requested artwork, inherits currentColor, and applies the selected size. It does not dispatch activation events or manage focus.

Interaction

Icon is not interactive or focusable. Place it inside the appropriate semantic control when it participates in an action.

Accessibility

Icons are decorative by default. Set a label only when the icon itself carries standalone meaning. Inside an icon-only Button, give the Button the accessible name and keep Icon decorative to avoid duplicate announcements.

Forms

Icon does not participate in forms. Form labeling, validation, disabled state, submission, and value semantics belong to the control that contains or accompanies it.

Styling

Icons inherit currentColor. The public stylesheet maps sm to 1rem, md to 1.25rem, and lg to 1.5rem. Stable hooks include data-vf-icon, data-vf-icon-name, data-vf-variant, data-vf-shape, and data-vf-size.

CSR and SSR

Framework ports can render SVG output during SSR where their runtime supports it. Elements becomes active after explicit registration and browser upgrade. Native Web requires no hydration.

Examples

The Quick start example demonstrates Bookmark in the selected framework. Prefer granular artwork imports such as @vyrnforge/icons/bookmark where the framework integration accepts an IconDefinition.

Do / Don't

Do keep decorative icons hidden from assistive technology and let an owning control provide the accessible name. Don't make Icon clickable by itself or invent fallback labels that were not authored by the application.

Testing guidance

Test observable semantics: decorative icons are hidden, meaningful standalone icons expose their label, requested presentation options are reflected, and the icon inherits the intended color and size. Depend only on documented APIs and hooks.

Compatibility

Documented artwork input, presentation options, accessibility behavior, and public styling hooks are shared compatibility commitments. Framework grammar remains idiomatic and is documented in the framework adaptation above. See the Compatibility reference for supported runtime and browser ranges.
