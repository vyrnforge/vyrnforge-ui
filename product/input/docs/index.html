Input styles a native text-entry control while preserving browser and form semantics.

Overview

Use Input for ordinary text-like form values. The browser remains responsible for editing, focus, value, submission, reset, and constraint validation.

Installation and imports

Load @vyrnforge/web/styles/input.css. React, Angular, and Vue use their /input package entrypoints; Native Web and Custom Elements applications use data-vf-input on a native input.

Quick start

Form workflows

VyrnForge preserves native form participation rather than introducing a shared form runtime. Applications own validation orchestration, drafts, persistence, routing, server field errors, duplicate-submission policy, and domain rules. Keep labels persistent, use meaningful native name, required, type, and autocomplete attributes, preserve entered values after errors, and connect authored help/error text to the control. Error summaries are a workflow pattern when submitted errors are hard to discover; they are not a requirement for a new component.

Conditional fields need an explicit retention and submission policy. Reset restores the workflow's defined baseline; cancel means abandoning the current editing flow and must not silently promise rollback of an already-sent operation.

Accessibility

Always provide an accessible name. Prefer a native <label> when practical. Keep disabled, readonly, required, and invalid semantics distinct. Dynamic validation must not steal focus. After an explicit blocked submission, an intentionally presented linked error summary may receive focus once when that improves recovery.

Styling

The stable styling hook is data-vf-input. Shared semantic tokens drive surface, text, border, focus, disabled, readonly, and invalid presentation.

Framework API

React and Vue expose Input; Angular exposes vfInput. The supported initial types are text, email, password, search, tel, and url. No <vf-input> custom element is introduced. Form state remains idiomatic to the consuming framework/application rather than becoming a VyrnForge-wide API.

Compatibility

The rebuild contract preserves native form behavior and uses the same canonical Web styling across implemented framework ports. The complete STD-06 profile-edit workflow is currently a declared React representative example; existing native-control evidence across other ports does not imply their full form adapters or application workflows were exercised.
