Separator is a native-first Layer 1 primitive for meaningful boundaries between adjacent content groups.

Overview

Use Separator to represent a visible and semantic boundary between adjacent groups of content. It is non-interactive and owns only separator semantics, orientation, and one-dimensional visual treatment.

Installation and imports

Native Web uses @vyrnforge/web/styles/separator.css. Framework entrypoints are @vyrnforge/react/separator, @vyrnforge/angular/separator, and @vyrnforge/vue/separator. Elements consumers use the Native Web contract directly.

Quick start

Anatomy

Separator renders or decorates one native hr boundary and has no child content.

Variants and sizes

The public contract exposes only orientation="horizontal | vertical". Visual variants, sizes, thickness, and length props are intentionally deferred.

State

Separator has no interactive or lifecycle state. Orientation is configuration rather than state.

Behavior

Horizontal is the native default. Vertical usage preserves hr semantics and adds aria-orientation="vertical".

Interaction

Separator is never focusable by VyrnForge and adds no pointer or keyboard behavior.

Accessibility

The native separator role is preserved. Vertical orientation is conveyed with aria-orientation="vertical". A consumer may intentionally add aria-hidden="true" for a purely decorative line.

Forms

Separator does not participate in form state, validation, or submission.

Styling

The stable hooks are data-vf-separator and data-vf-separator-orientation. Canonical Web CSS uses the shared semantic border color, logical properties, low-specificity selectors, and forced-colors support.

Framework API

React and Vue expose Separator; Angular exposes VfSeparatorDirective on an authored hr; Native Web uses the documented hooks. No dedicated custom element is required because native HTML already owns the semantic element.

CSR and SSR

Native Web needs no JavaScript or hydration. React, Angular, and Vue preserve native hr output and the stable hooks during SSR.

Examples

The basic executable example demonstrates the same semantic boundary contract across Native Web, React, Angular, and Vue.

Do / Don't

Do use Separator for meaningful group boundaries. Don't turn it into a spacing, responsive-layout, or generic border utility.

Testing guidance

Verify native hr semantics, stable hooks, vertical ARIA orientation, token-driven borders, forced-colors visibility, and absence of interaction.

Compatibility

Separator is defined for Native Web, React, Angular, and Vue in the rebuild channel. Elements consumption intentionally uses the Native Web contract rather than a redundant wrapper.
