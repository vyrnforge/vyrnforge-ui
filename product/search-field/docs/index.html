SearchField composes native search input behavior with an explicit clear control without owning search execution, routing, or results.

Overview

Use SearchField for a query input with a clear affordance. Search, autocomplete/suggestions, filters, sorting, and grouping are separate concepts; compose the smallest correct controls for each responsibility.

Installation and imports

Import from each framework's /search-field subpath and load @vyrnforge/web/styles/search-field.css.

Quick start

Anatomy

Search root, native search input, and clear button.

Variants and sizes

No result- or product-specific variants.

State

Supports controlled and uncontrolled query value. A consuming workflow may distinguish a draft query from the committed criteria currently governing results.

Behavior

Clear resets the query value and restores focus to the input according to the shared SearchField contract. Search execution remains consumer-owned. A workflow with explicit Search or Apply must keep draft and committed criteria distinct; an immediate-update workflow may commit each valid edit.

Interaction

The input and clear control remain native controls. Consumers choose submitted, immediate, or hybrid result-update behavior based on request cost, reversibility, latency, and multi-edit needs rather than a universal VyrnForge debounce or apply policy.

Accessibility

The root is a search landmark. The search input and icon-only clear action require authored accessible names appropriate to the product language. Reusable component behavior must not rely on hidden English copy. Text-composition keys must not be treated as ordinary submit/navigation commands while IME composition is active.

Forms

Consumers own submission, debouncing, validation, and result fetching.

Styling

Canonical CSS is Web-owned and token driven.

Framework API

Ports expose the same query and clear relationship idiomatically. A focused cross-port repair for clear naming, focus restoration, and real implementation evidence is tracked separately from the STD-08 exploration pattern.

CSR and SSR

Imports are server safe. URL parsing, history, query persistence, and data requests remain application-owned browser/integration behavior.

Examples

The basic example demonstrates query entry and clearing. The list-explorer example composes SearchField with Checkbox facets, NativeSelect sorting, Button actions, application-owned URL history, a deterministic fake data service, stale-response suppression, and zero-result recovery.

Search and data-exploration integration

SearchField clears only its query. A broader workflow-level reset may also clear filters and restore sort/group/page defaults. Durable committed criteria may be reflected in the URL when useful and safe, but VyrnForge does not own routing or serialization. Older asynchronous responses must not overwrite newer committed criteria. Zero matching results preserve active criteria and offer relevant recovery rather than masquerading as an empty collection.

Use Combobox when the interaction is editable selection from known options; do not create a duplicate Autocomplete component or use Combobox merely because a free-form search has results. Search suggestions must declare whether selection changes the query, selects a known value, or navigates.

Do / Don't

Do use SearchField for query entry and compose filters/sort/results at the workflow layer. Don't make the library own search services, URL state, recent/saved-search storage, typo correction, advanced-query parsing, or result ranking.

Testing guidance

Test query clear/focus behavior against real public entrypoints, authored accessible names, IME-safe submission where a workflow handles Enter, draft-versus-committed state, stale-response suppression, URL Back/Forward restoration when applicable, zero-result recovery, stable focus, and automated accessibility. Deterministic fake data proves integration mechanics, not production search quality or backend behavior.

Compatibility

SearchField is a shared concept across React, Angular, Vue, and Elements, but evidence must remain port- and revision-specific. STD-08's representative list explorer is a React integration example; it does not establish cross-framework search-service, router, native-platform, or production maturity.
