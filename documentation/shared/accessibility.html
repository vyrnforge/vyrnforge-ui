Accessibility is part of each component contract, not an optional enhancement layer.

Native semantics first

VyrnForge prefers native HTML semantics and browser behavior when they satisfy the contract. Library-owned ARIA is derived and wired when it can be done safely; consumers remain responsible for meaningful labels and application context that the library cannot infer.

Interaction evidence

Keyboard behavior, focus movement, disabled and read-only semantics, reduced motion, forced-colors behavior, directionality, and relevant assistive-technology considerations are documented and tested per component.

No generic compliance claim

Component documentation must explain concrete semantics, relationships, keyboard rules, focus behavior, and consumer responsibilities rather than relying on a generic compliance statement.
