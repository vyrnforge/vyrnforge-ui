VyrnForge components expose state and interaction in ways that fit the platform and your framework. Component guides document which state your application controls, which state the browser owns, and which callbacks or events report user intent.

Controlled state

When a component is controlled, an interaction can request a change without changing application-owned state by itself. Handle the documented callback or event, update your state, and pass the new value back through the component's public API.

Uncontrolled state

When an uncontrolled API is available, use the documented default value to establish initial state and let the component manage subsequent changes. Component pages identify whether controlled, uncontrolled, or both forms are supported.

Native behavior

Native browser behavior remains authoritative where the public component contract relies on it. Use documented properties, attributes, callbacks, and events instead of attempting to synchronize the same state through application-specific DOM bookkeeping.

Meaningful distinctions

Keep different states distinct: loading is not automatically disabled, selected is not the same as focused, invalid is not the same as an error message, and open state is not the same as a dismissal request. Each component guide explains the distinctions that apply.
