VyrnForge standardizes semantic state, behavior policy, and interaction intent without forcing every framework through one shared state runtime.

Intent is not committed state

An interaction may request a state change without guaranteeing that externally controlled state changes. Framework ports deliver intent idiomatically; the consumer owns committed state when a component is controlled.

Browser truth

Native browser state should not be mirrored into a generic VyrnForge store without a demonstrated need. Browser effects follow committed state and must be safe to reconcile during activation or hydration.

Meaningful distinctions

Public documentation preserves distinctions such as loading versus disabled, selected versus focused, invalid versus an error message, and open state versus a dismissal request.
