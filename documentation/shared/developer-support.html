Developer support starts with canonical documentation, executable examples, inspectable diagnostics, and reproducible issue reports. This page collects the common questions that otherwise turn into undocumented tribal knowledge.

Executable examples as playgrounds

Component pages embed executable examples owned by the same component slice as its implementation evidence. Use those examples as the canonical playground for supported APIs rather than copying internal fixtures or undocumented markup.

Frequently asked questions

Do I need a VyrnForge theme provider?

No. Runtime theming uses CSS custom properties and data-vf-theme. Framework-specific providers are not the source of theme truth.

Is the reset mandatory?

No. The reset is an explicit optional stylesheet. Components must remain usable without requiring an application-wide reset.

Should every framework render identical source code?

No. Framework ports are idiomatic siblings. They must preserve the same semantics, accessibility, design language, behavior, and test intent without sharing one universal renderer.

Can I depend on private CSS variables or internal helpers?

No. Only documented public contracts are compatibility commitments. Private aliases and implementation details may change without notice.

Why is a documented component unavailable in one framework?

Multi-framework architecture does not imply every framework surface ships at the same time. The relevant component and framework documentation must explicitly show what is implemented.

Where to start when something fails

Use the Diagnostics & Troubleshooting guide to identify whether the failure is package, token/CSS, browser, SSR, documentation, or component behavior related. Then reduce the problem to the smallest public surface that reproduces it.

Reporting a problem

Report issues with a minimal reproduction and the diagnostics listed in the troubleshooting guide. Include the affected public package/subpath and avoid relying on private implementation details as the reproduction contract.
