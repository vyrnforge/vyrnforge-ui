Application tests should verify the observable VyrnForge contract rather than private framework or DOM implementation details.

What to test

  • Query by accessible role, name, or other public semantics where practical.
  • Exercise keyboard and focus behavior when it is part of the component contract.
  • Test semantic intent separately from committed state for controlled components.
  • Use documented public CSS hooks only when a styling assertion is actually required.

What not to test

  • Undocumented DOM nesting or framework-internal lifecycle details.
  • Private --_vf-* custom properties or internal state markers.
  • Implementation helpers that are not part of the public package surface.

Framework examples

Framework-specific test syntax belongs to the corresponding framework guide once that port has real implemented components. The testing philosophy on this page remains shared.
