Application tests should verify observable VyrnForge behavior through documented public APIs and accessible semantics.

What to test

  • Query by accessible role, name, or another user-visible semantic where practical.
  • Exercise documented keyboard and focus behavior for interactive components.
  • For controlled components, verify both the change request and the application state update.
  • Assert documented public styling hooks only when visual state is part of the behavior you need to prove.

What not to test

  • Undocumented DOM nesting, attributes, classes, or generated markup.
  • Framework lifecycle details that are not part of the component API.
  • Implementation details that are not documented as supported extension points.

Framework tests

Use your framework's normal testing tools and interact with VyrnForge through the same public component APIs your application uses. Component guides call out behavior that needs real-browser coverage, such as focus movement, keyboard interaction, modal behavior, or hydration.
