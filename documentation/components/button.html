Status: first new-generation component baseline.

Button triggers an immediate action or command and uses a real HTML <button> as its semantic baseline. Navigation remains a link concern.

Installation and imports

Load @vyrnforge/web/styles/button.css for the granular stylesheet or @vyrnforge/web/styles.css for the aggregate Web foundation. React, Angular, and Vue expose ./button package subpaths.

Quick start

<button data-vf-button data-vf-variant="primary" data-vf-size="md" type="button">Save</button>

The native type default is intentionally not overridden. Inside a form, an omitted type therefore preserves native submit behavior.

Anatomy

Button has no required compound anatomy. Text, icons, and inline content use normal framework composition; the baseline does not introduce icon-specific props or slots.

Variants and sizes

The stable presentation axes are primary, secondary, and ghost, with primary as the default; sizes are sm, md, and lg, with md as the default.

State and behavior

disabled uses the native disabled attribute. loading means work is in progress and is independent from disabled: it adds aria-busy="true" and the loading styling hook but remains focusable and activatable unless the consumer also disables the button.

Interaction

Pointer activation, Enter/Space keyboard activation, focus, and form behavior are browser-owned. VyrnForge does not reproduce native key handling in JavaScript. Focus styling uses :focus-visible.

Accessibility

Consumers provide an accessible name with visible content or an appropriate platform naming mechanism. VyrnForge does not invent English fallback labels or redundant roles. The loading indicator is decorative, forced-colors receives explicit usable treatment, and reduced-motion disables spinner animation and transitions.

Forms

Submit, reset, explicit type="button", name, value, form, and native form override attributes remain platform capabilities. VyrnForge does not own application form state.

Styling and customization

Canonical CSS lives in @vyrnforge/web under the VyrnForge cascade layers. Stable DOM hooks are data-vf-button, data-vf-variant, data-vf-size, and data-vf-loading. Styling uses semantic --vf-* tokens and private --_vf-* calculations; private variables are not compatibility API.

CSR, SSR, and hydration

The server markup is already a functional native button. React, Angular, and Vue hydration adds framework event wiring without changing the Button semantic state. Native Web requires no hydration.

Framework APIs

React uses Button with native button props/ref plus variant, size, and loading. Angular uses the standalone VfButtonDirective on <button vfButton>. Vue uses Button, native fallthrough attributes, and default-slot content. Elements Button is deliberately deferred until a portable strategy can preserve native button and form semantics without reimplementation.

Testing guidance

Prefer role/name queries and test observable activation or form outcomes. Real-browser conformance owns keyboard activation, focus-visible, form participation, reduced motion, forced-colors, directionality, hydration, accessibility scanning, and the limited visual baseline.

Do / Don't

Do: use Button for actions and set disabled explicitly when repeat activation must be blocked during loading. Don't: use Button as a navigation link or assume loading automatically disables activation.
