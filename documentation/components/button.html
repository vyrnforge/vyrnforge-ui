Button triggers an action or command. It keeps the platform's native <button> semantics while VyrnForge supplies shared styling, state hooks, and idiomatic framework adapters.

Overview

Use Button for actions such as saving, confirming, opening a UI, or submitting a form. Use a link for navigation to another location. Button deliberately keeps native activation, focus, keyboard, and form behavior instead of recreating those behaviors in JavaScript.

Anatomy

Button has one public semantic element: the button itself. Text, icons, and other inline content use normal framework composition. There is no required compound anatomy or icon-specific slot in the baseline API.

Variants and sizes

Use primary for the strongest action, secondary for an alternative action, and ghost for lower-emphasis actions. Sizes are sm, md, and lg; md is the default.

State

disabled and loading are different states. Disabled uses native disabled semantics and prevents activation. Loading exposes busy state with aria-busy and a visual progress indicator, but it does not automatically disable the button. Set both when repeated activation must be prevented while work is in progress.

Behavior

VyrnForge does not add an invented activation event. Consumers use the framework's normal native click/event surface. The browser remains responsible for activation and form participation.

Interaction

Pointer activation and Enter/Space keyboard activation follow native button behavior. Focus remains browser-owned and VyrnForge styles keyboard-visible focus with :focus-visible.

Accessibility

Provide an accessible name through visible content or an appropriate platform naming mechanism. VyrnForge does not add redundant roles or fallback English labels. Loading preserves the button's accessible name while exposing busy state. Forced-colors and reduced-motion treatments are included in the shared Web stylesheet.

Forms

Button preserves native form behavior. If type is omitted inside a form, the browser's native submit default remains in effect. Native attributes such as name, value, form, and form override attributes remain available through the framework's native attribute surface.

Styling

The shared implementation lives in @vyrnforge/web. Stable styling hooks are data-vf-button, data-vf-variant, data-vf-size, and data-vf-loading. Prefer public --vf-* tokens for customization; --_vf-* variables are private implementation details.

CSR and SSR

The semantic button exists in server output before hydration. React, Angular, and Vue add their framework event wiring during client activation without replacing Button's semantic state model. Native Web does not require hydration.

Examples

The Quick start playground is the first executable Button example. Additional state, forms, composition, and accessibility examples should be added as separate checked-in executable examples rather than copied code blocks.

Do / Don't

Do use Button for actions and explicitly disable it when repeated activation must be blocked. Don't use Button as a navigation link or assume loading automatically prevents activation.

Testing guidance

In application tests, query Button by role and accessible name and assert observable outcomes such as activation or form submission. Avoid depending on private CSS variables or internal implementation details.

Compatibility

Framework/runtime and browser support comes from VyrnForge's generated compatibility reference. A framework surface that is not implemented is not presented here as shipped support.
