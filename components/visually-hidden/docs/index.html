VisuallyHidden keeps meaningful content in the accessibility tree while removing it from ordinary visual presentation.

Overview

Use VisuallyHidden when content must remain available to assistive technology without taking meaningful visual layout space. It is an accessibility primitive, not a generic visibility system.

Installation and imports

Native Web can load @vyrnforge/web/styles/foundation.css or the granular alias @vyrnforge/web/styles/visually-hidden.css. Framework entrypoints are @vyrnforge/react/visually-hidden, @vyrnforge/angular/visually-hidden, and @vyrnforge/vue/visually-hidden. Elements consumers use the Native Web contract directly.

Quick start

Anatomy

VisuallyHidden has one native host containing consumer-authored accessible content.

Variants and sizes

There are no visual variants or size props. React and Vue may choose from the supported semantic native host elements; the default is span.

State

VisuallyHidden has no component state and never toggles itself.

Behavior

The shared Web foundation applies the canonical accessible-hiding treatment through data-vf-visually-hidden. Framework ports do not duplicate that CSS.

Interaction

VisuallyHidden adds no focus, pointer, keyboard, announcement, or event behavior. Focus-reveal and skip-link behavior are separate future capabilities.

Accessibility

The primitive keeps content represented in the accessibility tree. It does not apply aria-hidden, hidden, inert, display:none, or visibility:hidden.

Forms

VisuallyHidden does not own form value, validation, labels, or submission behavior. Consumers choose semantically appropriate native content.

Styling

The stable hook is data-vf-visually-hidden. The canonical low-specificity hiding recipe remains in shared foundation CSS; the granular component stylesheet aliases that same source rather than creating a second implementation.

Framework API

React and Vue expose VisuallyHidden with a constrained native as choice; Angular exposes VfVisuallyHiddenDirective; Native Web applies the stable data hook directly. No dedicated custom element is required.

CSR and SSR

Native Web requires no JavaScript or hydration. React, Angular, and Vue preserve the native host, accessible content, and stable hook during SSR.

Examples

The basic executable example demonstrates an accessible hidden label across Native Web, React, Angular, and Vue.

Do / Don't

Do use VisuallyHidden for meaningful assistive content. Don't use it as responsive display, disclosure state, or a substitute for intentionally visible focusable content.

Testing guidance

Verify the shared hook, preserved content and native semantics, absence of accessibility-tree-removing attributes/styles, and zero framework-specific hiding CSS.

Compatibility

VisuallyHidden is defined for Native Web, React, Angular, and Vue in the rebuild channel. Elements consumption intentionally uses the Native Web contract.
