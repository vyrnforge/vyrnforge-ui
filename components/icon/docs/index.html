Icon is VyrnForge's non-interactive SVG primitive. The initial foundation ships one authored Bookmark glyph to establish shared rendering, accessibility, sizing, and visual-family semantics before the catalog grows.

Overview

Use Icon for symbolic visual content that accompanies or communicates UI meaning. Icon is deliberately non-interactive: actions and navigation still belong to Button, Link, or another semantic control.

Installation and imports

Load the canonical Web icon stylesheet, import bookmarkIcon from @vyrnforge/web/icon, and use the renderer-specific Icon surface for your framework.

Anatomy

Icon has one semantic visual element: an SVG whose paths come from an IconDefinition. Framework adapters translate that shared definition into their native rendering model. The path structure is internal artwork, not a composition API.

Variants and sizes

variant is outlined or filled. shape is rounded or sharp. These are independent axes, with outlined + rounded as the default. Sizes are sm, md, and lg; md is the default.

State

Icon has no interactive state of its own. Selected, disabled, invalid, busy, or pressed state belongs to the component or application concept that owns the icon. A consumer may deliberately choose a different authored icon variant to support that owning state, but Icon does not infer semantic state from fill or shape.

Behavior

Icon resolves the requested authored variant and shape, renders the resulting SVG paths, inherits currentColor, and applies the canonical size hook. It does not dispatch events, manage focus, or register global icon names.

Interaction

Icon is not focusable and does not provide pointer or keyboard interaction. Place it inside the appropriate semantic interactive component when an icon participates in an action.

Accessibility

Icons are decorative by default and hidden from assistive technology. Set label only when the icon itself carries standalone meaning; that produces image semantics with the supplied accessible name. Inside an icon-only Button, the Button owns the accessible name and Icon remains decorative to avoid duplicate announcements.

Forms

Icon does not participate in forms. When used inside a form control or form-related component, labeling, validation, disabled state, submission, and value semantics remain owned by that control.

Styling

Icons inherit currentColor. The canonical stylesheet maps sm to 1rem, md to 1.25rem, and lg to 1.5rem. Stable hooks include data-vf-icon, data-vf-icon-name, data-vf-variant, data-vf-shape, and data-vf-size. Private --_vf-* variables are implementation details.

Framework API

CSR and SSR

React, Angular, and Vue render semantic SVG output on the server without requiring browser globals. Elements keeps module definition server-safe and performs custom-element rendering after browser connection. Native Web requires no hydration.

Examples

The Quick start example demonstrates Bookmark across Native Web, React, Angular, Vue, and Elements. Additional glyphs should be added as checked-in executable examples when real component or product needs justify them.

Do / Don't

Do keep decorative icons hidden from assistive technology and let an owning Button or Link provide the accessible name. Don't make Icon clickable by itself, invent fallback English labels, or treat a CSS stroke change as a substitute for deliberately authored icon artwork.

Testing guidance

Assert observable icon semantics: decorative icons are hidden, meaningful standalone icons expose their label, variant/shape/size hooks reflect the public API, and the SVG inherits the intended color and canonical size. Avoid coupling tests to private path ordering or private CSS variables.

Compatibility

The first Icon slice is implemented for Native Web, React, Angular, Vue, and Elements. Broader browser and release qualification remains governed by VyrnForge's compatibility evidence rather than being inferred from this component page.
