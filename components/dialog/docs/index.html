Dialog presents focused modal content using the browser-native <dialog> and showModal() model while keeping dismissal intent, focus lifecycle, and state consistent across framework ports.

Overview

Use Dialog for modal content that temporarily requires attention or a decision. VyrnForge relies on the native top layer rather than introducing a global overlay stack or framework-neutral focus-trap runtime.

Anatomy

A Dialog contains a native dialog root, authored title, optional description, body content, and consumer-authored controls. Stable hooks are data-vf-dialog-root, data-vf-dialog-title, data-vf-dialog-description, data-vf-dialog-body, and data-vf-dialog-close.

State and dismissal

Open state may be controlled or initialized as uncontrolled state. Escape, optional backdrop activation, and close controls produce a dismissal request with reason escape, backdrop, or close-control. Preventing the request leaves controlled state and the native modal open.

Focus

Native dialog focusing behavior is the default. Framework ports support an explicit initial-focus target and restore focus to the previously focused meaningful element when the dialog closes and that target is still valid.

Accessibility

The root is a native <dialog> activated with showModal(); VyrnForge does not emulate modality with role="dialog" and aria-modal. Title relationships are generated from the root identifier. Supply descriptionId when a description part should be referenced by aria-describedby. Consumers own all visible labels and control text.

CSR and SSR

Server output never claims client-side modality by serializing an open attribute. Intended open state may be exposed through data-vf-open; after client activation the framework port synchronizes the native element with showModal() or close().

Framework API

React exports DialogRoot, DialogTitle, DialogDescription, DialogBody, and DialogClose. Vue exposes the same compound concepts with modelValue/update:modelValue. Angular uses standalone native-element directives rooted at dialog[vfDialogRoot]. All ports expose the same dismissal reasons.

Behavior boundaries

Dialog does not own application confirmation logic, generic outside-click handling, arbitrary portals, body-scroll locking, a universal overlay manager, or a universal focus manager. Nested modals rely on the browser top layer.

Testing guidance

Real-browser tests should prove native modal activation, background inertness, Escape cancellation, optional backdrop dismissal, close controls, initial focus, restoration, nested modals, hydration, reduced motion, forced colors, and accessibility.

Compatibility

The current interactive ports are React, Angular, and Vue with canonical styling from @vyrnforge/web. A Web Components Dialog surface is not currently shipped.
