Dialog presents focused modal content using the browser-native <dialog> and showModal() model while keeping dismissal intent, focus lifecycle, and state consistent across framework ports.

Overview

Use Dialog for modal content that temporarily requires attention or a decision. VyrnForge relies on the native top layer rather than introducing a global overlay stack or framework-neutral focus-trap runtime.

Anatomy

A Dialog contains a native dialog root, authored title, optional description, body content, and consumer-authored controls. The title and description relationships are library-owned when the corresponding compound parts are used, while consumers own all meaningful visible text.

Variants and sizes

Dialog has no public semantic variants or size enum in the current contract. Consumers may compose responsive layout around the canonical styling hooks without changing modal semantics or dismissal behavior.

State

Open is component state. React supports controlled open or uncontrolled defaultOpen; Vue uses modelValue with optional defaultOpen; Angular supports an open input with optional defaultOpen. Controlled ports notify state owners rather than unilaterally changing consumer-owned state.

Behavior

Opening a Dialog activates the native element with showModal() on the client. Escape, optional backdrop activation, and close controls produce a preventable dismissal request with reason escape, backdrop, or close-control. A prevented request keeps the modal open. If a native close occurs while controlled state still says open, the framework port resynchronizes the native element instead of leaving browser state and framework state split.

Interaction

Escape follows the native dialog cancel path. Backdrop dismissal is opt-in and is recognized only when pointer activation begins and ends on the dialog backdrop surface; content interactions are not treated as outside clicks. Close controls request dismissal explicitly. Nested modal ownership remains with the topmost native dialog.

Accessibility

The root is a native <dialog> activated with showModal(); VyrnForge does not emulate modality with role="dialog" and aria-modal. Title relationships are generated from the root identifier. Supply descriptionId when a description part should be referenced by aria-describedby. Native initial focus is the default, an explicit initial-focus target is optional, and focus is restored to the previous meaningful target after close when that target remains valid.

Forms

Dialog does not define submission, validation, confirmation, or reset policy. Forms may be composed inside a Dialog, but application form behavior remains owned by the consuming application and the controls used within it.

Styling

Stable hooks are data-vf-dialog-root, data-vf-dialog-title, data-vf-dialog-description, data-vf-dialog-body, and data-vf-dialog-close, with state/policy hooks data-vf-open and data-vf-backdrop-dismiss. The native ::backdrop pseudo-element is the canonical backdrop styling surface. Shared CSS includes responsive sizing, overflow behavior, visible focus, reduced-motion safety, and forced-colors treatment.

CSR and SSR

Server output is semantically valid but never claims client-side modality by serializing an open attribute. Intended open state may be exposed through data-vf-open; after client activation the framework port synchronizes the native element with showModal() or close(). Stable title and description identifiers preserve relationships through hydration without premature focus movement.

Examples

The basic executable example demonstrates the native Dialog structure, shared styling, title and description relationships, close controls, optional backdrop dismissal, and equivalent public concepts in React, Angular, and Vue.

Do / Don't

Do use Dialog for genuinely modal tasks, provide meaningful authored title text, and keep dismissal policy explicit. Don't use Dialog as a generic popover, application router, global notification surface, or reason to introduce document-wide outside-click, scroll-lock, overlay-stack, or focus-manager infrastructure.

Testing guidance

Use real-browser tests to prove native modal activation, background inertness, Escape cancellation, optional backdrop dismissal, close controls, initial focus, focus restoration, nested modals, hydration, reduced motion, forced colors, and accessibility. SSR tests should verify state and relationships without an open attribute.

Compatibility

The current interactive ports are React, Angular, and Vue with canonical styling from @vyrnforge/web. A Web Components Dialog surface is not currently shipped; the existence of @vyrnforge/elements does not imply one.
