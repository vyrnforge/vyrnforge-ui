SplitButton preserves a primary action while exposing related secondary commands from a separate menu trigger.

Overview

Use SplitButton when one action is dominant and a small set of alternatives remains closely related.

Installation and imports

Import from the framework-specific /split-button subpath and load @vyrnforge/web/styles/split-button.css together with Menu styling.

Quick start

Anatomy

Root, primary Action, menu Trigger, Content, and Item compose the public control.

State

The menu disclosure state is separate from primary action execution state.

Behavior

The primary action never opens the menu; the adjacent trigger exclusively controls secondary commands and reuses Menu behavior.

Interaction

Both controls remain native buttons; the menu trigger follows Menu keyboard navigation, dismissal, and focus restoration.

Accessibility

The primary and menu controls have independent accessible names, and only the menu trigger exposes popup and expanded state.

Forms

Both controls default to non-submitting button behavior; consumers deliberately opt into form submission semantics where needed.

Styling

Canonical CSS is Web-owned and token driven, with visual adjacency that does not merge the two semantic actions.

Framework API

Ports expose the same primary-action/menu-disclosure separation idiomatically.

CSR and SSR

Imports are server safe; popup positioning and dismissal begin only after browser rendering.

Do / Don't

Do use when one action is clearly primary. Don't hide unrelated commands or application routing/state inside the component.

Testing guidance

Test primary activation independence, menu opening and keyboard behavior, dismissal, focus restoration, SSR, and axe.

Compatibility

React, Angular, Vue, and Elements implement sibling SplitButton ports composed from the shared Menu concept.
