Menu presents a transient set of commands with menu-button semantics, managed item focus, keyboard navigation, dismissal, and focus restoration.

Overview

Use Menu for a transient set of contextual commands opened from a button. The current Menu contract is a single vertical menu; nested submenus and menubars are separate concepts rather than implicit behavior.

Installation and imports

Import from each framework's /menu subpath and load @vyrnforge/web/styles/menu.css.

Quick start

Anatomy

Root owns open state, Trigger opens the menu, Content owns role="menu", Item represents a command, and Separator groups commands visually and semantically.

State

Supports controlled and uncontrolled open state where the framework port exposes that model. Disabled menu items remain focusable as part of menu keyboard navigation but expose aria-disabled="true" and cannot activate.

Behavior

Opening from Enter, Space, or Down Arrow moves focus to the first item; Up Arrow opens and moves focus to the last item. Activating an enabled command closes the menu and restores focus to its trigger. Escape closes without activation and restores the trigger. Tab or Shift+Tab closes the transient menu and continues page focus navigation instead of moving among menu items.

Interaction

Down/Up Arrow move through menu items with wrapping, including disabled items; Home/End move to the first or last item; printable-character typeahead moves focus by item text. Enter and Space use native button activation for enabled command items. The current contract does not define submenu Left/Right Arrow behavior.

Accessibility

The trigger is a native button with aria-haspopup="menu" and aria-expanded. Content uses role="menu"; command items use role="menuitem" and tabindex="-1". Consumers provide the menu's meaningful accessible name with aria-label or aria-labelledby on Content and meaningful command labels on items. VyrnForge owns open-state semantics, item roles, managed focus, disabled semantics, and trigger restoration.

Forms

Menu is not a form control. Command items default to non-submitting button behavior; applications own command effects, form state, validation, and workflow transitions.

Styling

Canonical CSS is Web-owned and token driven. Visible focus must remain distinct from disabled and hover presentation, including forced-colors environments.

Framework API

React, Angular, Vue, and Elements expose the same command-menu semantics idiomatically. No global focus or accessibility runtime is introduced; pure collection navigation and typeahead calculations are reused from Core.

CSR and SSR

Imports are server safe. Browser-only focus movement, positioning, and dismissal behavior begins only after client activation. Consumers should not rely on server markup alone to emulate an opened interactive menu.

Do / Don't

Do use Menu for application commands that fit desktop-style menu interaction. Don't use Menu merely to style ordinary navigation links or a persistent group of buttons; prefer native navigation or Toolbar when those semantics fit better.

Testing guidance

Test trigger keyboard opening, first/last focus, Up/Down, Home/End, typeahead, focusable disabled commands, enabled activation, Escape restoration, Tab exit, controlled/uncontrolled state where applicable, SSR-safe imports, and automated accessibility guardrails.

Compatibility

React, Angular, Vue, and Elements implement the shared Menu accessibility contract. Port-local positioning or pointer-dismissal mechanics may differ and require their own evidence; they are not the semantic source of truth.
