SideNav provides grouped application or documentation navigation while preserving native link behavior and consumer-owned route state.

Overview

Use SideNav for persistent application or documentation destinations that benefit from grouping and current-page indication. SideNav standardizes navigation semantics and styling without becoming a router or command system.

Installation and imports

Import from the framework-specific /side-nav subpath and load @vyrnforge/web/styles/side-nav.css, or load the aggregate @vyrnforge/web/styles.css.

Quick start

Anatomy

SideNav composes a navigation landmark from authored groups, group labels, lists, items, and native destination links. Product icons, badges, counts, and other content remain authored children.

State

Consumers determine the current destination. Current-page state is represented on the actual destination link with aria-current="page"; SideNav does not inspect a pathname, router context, or global application state.

Behavior

Links preserve normal browser navigation behavior including modifier-click, open-in-new-tab, copy-link-address, and progressive enhancement. SideNav does not replace destinations with button or div navigation and does not introduce a tree-navigation controller.

Accessibility

Provide an authored accessible name when multiple navigation landmarks can exist. Keep destinations as native links, place aria-current="page" on the current link, preserve DOM keyboard order, and rely on shared visible focus treatment.

Styling

Canonical styling is owned by @vyrnforge/web, uses shared tokens and logical properties, and exposes data-vf-side-nav* hooks. Current-page styling remains coupled to semantic current-link state rather than router-specific classes.

Framework API

React and Vue expose navigation composition components, Angular exposes standalone directives on authored navigation elements, and Elements exposes an explicitly registered SideNav root while authored native links and data hooks preserve the same contract.

CSR and SSR

SideNav imports are server-safe and static navigation requires no client JavaScript. Router libraries may supply authored destination links through documented composition hooks without becoming VyrnForge dependencies.

Do / Don't

Do use SideNav for application destinations and let consumers own URLs and current state. Don't use it for command execution, route guards, permissions, authentication, or automatic router discovery.

Testing guidance

Test navigation landmark naming, native link behavior, current-page semantics, focus visibility, keyboard traversal, forced-colors presentation, RTL layout, SSR safety, and consumer-router composition where applicable.

Compatibility

React, Angular, Vue, and Elements implement sibling SideNav ports, with Native Web providing the canonical shared CSS and markup hooks.
