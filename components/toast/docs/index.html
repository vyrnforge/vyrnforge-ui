Toast provides a polite notification viewport and dismissible notification anatomy without owning application messaging queues or domain events.

Overview

Use Toast for transient non-blocking status messages.

Installation and imports

Import from each framework's /toast subpath and load @vyrnforge/web/styles/toast.css.

Quick start

Anatomy

Viewport, root, title, description, and close control.

Variants and sizes

No product-specific severity taxonomy is imposed.

State

Root open state can be controlled; duration is an optional dismissal policy.

Behavior

The viewport announces additions politely and close dismisses the authored notification.

Interaction

The close control remains a native button.

Accessibility

The viewport uses live-region semantics and notifications retain authored readable content.

Forms

Not form-associated.

Styling

Canonical CSS is Web-owned and token driven.

Framework API

Ports expose the same notification anatomy idiomatically.

CSR and SSR

Imports are server safe; timers only start for mounted open notifications.

Examples

The basic example shows a persistent notification that can be dismissed.

Do / Don't

Do use for transient status. Don't make the library own domain event buses or persistence.

Testing guidance

Test live-region semantics, dismissal, duration policy, SSR, and axe.

Compatibility

React, Angular, Vue, and Elements implement the shared concept.
