Toast provides a polite notification viewport and dismissible notification anatomy without owning application queues, severity policy, persistence, or domain actions.

Overview

Use Toast for transient, non-blocking status content. The viewport is the polite live region; individual toast roots do not force focus or an assertive role.

Installation and imports

Import from each framework's /toast subpath and load @vyrnforge/web/styles/toast.css.

Quick start

Anatomy

Viewport, root, title, description, and native button close control. Keep roots inside the viewport so additions use the component's single polite announcement strategy.

State ownership

When a controlled open value is supplied, it is authoritative. Close controls and timers request false; the toast stays visible until the owner commits the closed state. Without open, each port owns local state initialized once from defaultOpen, which defaults to true. Later default changes do not reset live state.

Duration and pause behavior

The default duration is 5000 ms. Only finite positive durations arm a timer. 0, negative values, and non-finite runtime values are persistent. A duration change restarts the current open cycle with the new duration. Ordinary rerenders and callback identity changes do not move the deadline.

Pointer hover and keyboard focus inside the toast pause the same remaining-time budget. The timer resumes only after all active pause reasons clear. A rejected timeout produces one close request for that committed open cycle; a real close then reopen starts a fresh full duration.

Accessibility

The viewport uses aria-live="polite" with relevant additions/text, and showing a routine status does not move focus. Close controls remain native buttons. VyrnForge does not inject an English accessible name: author visible close text, aria-label, or aria-labelledby appropriate to the user's language. For example, an icon-only Indonesian close control can use aria-label="Tutup notifikasi". Browser evidence verifies DOM semantics and focus behavior; it does not claim a particular spoken screen-reader output. Manual assistive-technology observations remain separate evidence.

Close controls and names

Consumer click cancellation is respected before a close is requested. Leaving an icon-only close control unnamed is a consumer error.

Consumer boundary

The application owns the notification queue, message text, severity policy, persistence/history, business actions, retry safety, and localization. If timed content is the only access to essential information or an essential action, provide persistent or otherwise accessible alternative access rather than relying on a transient toast.

Elements compatibility

defineToastViewportElement() retains its existing registration signature. Use defineToastRootElement() and <vf-toast> for controlled, timed, or pausable root behavior. Existing authored data-vf-toast-root markup inside the viewport keeps its legacy uncontrolled close-by-removal behavior; externally controlled roots should migrate to <vf-toast> so close actions dispatch intent instead of deleting authored DOM.

Styling

Canonical Toast presentation remains Web-owned and token-driven through @vyrnforge/web/styles/toast.css. This repair changes state, timing, naming, and evidence behavior without introducing a visual redesign.

Framework API

React uses open, defaultOpen, duration, and onOpenChange. Angular uses the equivalent root inputs plus openChange. Vue uses open, defaultOpen, duration, and update:open. Elements uses VfToastRootElement, defineToastRootElement(), the open/defaultOpen/duration properties, and vf-open-change. API spelling is framework-idiomatic while observable state ownership remains equivalent.

CSR and SSR

React, Angular, and Vue render stable server semantics without starting timers during server rendering. Client activation owns timers and event listeners. Elements register explicitly in the browser and clear timers/listeners when disconnected.

Testing guidance

Test real public port implementations for controlled and uncontrolled close behavior, duration changes, rejected timeout requests, pause/resume, localized naming, focus preservation, teardown, SSR where applicable, and accessibility guardrails. A synthetic HTML click handler is not component conformance evidence.

Compatibility

React, Angular, Vue, and Elements expose idiomatic APIs with equivalent observable state, timing, naming, and focus behavior. Web remains the shared static styling/semantic baseline rather than a framework runtime.
