Build page structure with focused primitives: Container for content bounds, Stack for block flow, Cluster for wrapping inline groups, and Grid for intrinsic repeated-item layouts.

Start with the browser's layout model.VyrnForge adds shared intent and defaults without replacing CSS Grid, Flexbox, container queries, or semantic HTML.

Overview

Each primitive owns one job. Container constrains page or section content. Stack creates block-axis rhythm. Cluster groups inline content and wraps it. Grid creates equal flexible tracks for repeated peers and changes track count from available space.

Container

Content bounds and logical gutters.

<main data-vf-container data-vf-container-size="lg">…</main>

Stack

Block-flow rhythm between related siblings.

<section data-vf-stack data-vf-stack-gap="lg">…</section>

Cluster

Wrapping inline groups such as actions or tags.

<div data-vf-cluster data-vf-cluster-gap="sm">…</div>

Grid

Repeated peers that need intrinsic equal tracks.

<section data-vf-grid data-vf-grid-gap="md">…</section>

Quick start

A typical page composes Container and Stack, then uses Grid for repeated content and Cluster for compact actions.

Spacing

Stack

Stack is block-flow only. It exposes tokenized gap plus alignment and justification for its single flex axis. It does not switch direction or wrap.

Cluster

Cluster is inline flow with wrapping enabled. Use it for actions, tags, filters, and compact control groups. Inline order follows document direction, including RTL.

Grid

Grid is for repeated peers such as cards, summaries, galleries, or dashboard tiles. It uses equal flexible tracks and auto-fit, so the number of columns follows available inline space rather than viewport breakpoint props.

The framework API intentionally exposes only gap. The default minimum item width is 16rem. When a repeated-item family needs another minimum, override the public component token --vf-grid-min-item-size in CSS.

.account-cards {
  --vf-grid-min-item-size: 12rem;
}

Use ordinary CSS Grid for explicit column counts, named areas, item placement, alignment, spanning, dense packing, or layouts whose tracks have different meanings. Grid is not a 12-column system and does not reorder content.

Container

Container sizes are content bounds, not viewport breakpoints: sm 40rem, md 48rem, lg 64rem, xl 80rem, 2xl 96rem, and full without a maximum. Logical gutters work in LTR and RTL.

Installation and imports

Load @vyrnforge/web/styles/layout.css once, then use the surface appropriate to the application.

React / Vue

import { Cluster, Container, Grid, Stack } from '@vyrnforge/react/layout';

Angular

import { VfClusterDirective, VfContainerDirective, VfGridDirective, VfStackDirective } from '@vyrnforge/angular/layout';

Elements

import { defineLayoutElements } from '@vyrnforge/elements/layout';

Accessibility

Layout primitives add no ARIA roles, keyboard model, or source-order manipulation. Keep semantic HTML and logical reading order. React and Vue use as; Angular decorates authored elements; Elements remain semantically neutral.

Styling

Canonical CSS lives in @vyrnforge/web with low specificity. Use spacing tokens and the documented --vf-grid-min-item-size component token; use ordinary CSS beyond the focused primitive contracts.

Framework API

React / Vue

Stack: as, gap, align, justify. Cluster: the same inline-group options. Grid: as, gap. Container: as, size, gutter.

Angular

vfGrid exposes vfGridGap; other grid decisions remain CSS. Stack, Cluster, and Container retain their focused directive contracts.

Native Web

Use data-vf-grid and data-vf-grid-gap alongside the existing Stack, Cluster, and Container hooks.

Elements

defineLayoutElements() registers <vf-grid> with the other layout elements. <vf-grid gap="md"> emits the same shared DOM contract.

Compatibility

The exported layout APIs, documented data attributes, Elements attributes, spacing tokens, and --vf-grid-min-item-size are compatibility commitments.
