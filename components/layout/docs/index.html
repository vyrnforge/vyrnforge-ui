Build page structure with two simple jobs: use Container to control readable content width and gutters, then use Stack to create consistent space between related items.

Start with the browser's layout model.VyrnForge layout primitives add shared spacing and predictable defaults without replacing CSS Grid, Flexbox, container queries, or semantic HTML.

Overview

The first layout foundation is intentionally small. Container handles centered content bounds. Stack handles one-dimensional flow. Together they cover common page, section, form, card, and action-group layouts without creating a utility framework.

Container

Use it around page or section content that needs a maximum inline size and consistent logical gutters.

<main data-vf-container data-vf-container-size="lg">…</main>

Stack

Use it when siblings should flow in one direction with a shared gap instead of individual margins.

<section data-vf-stack data-vf-stack-gap="lg">…</section>

Quick start

A typical page composes a constrained Container with block-direction Stacks for sections and an inline Stack for actions. The example keeps the same layout vocabulary across every supported surface.

Spacing

Layout uses one public spacing vocabulary rather than arbitrary pixel props. The scale is available as CSS custom properties and through typed gap/gutter options.

none--vf-space-none0
xs--vf-space-xs0.25rem

md--vf-space-md1rem

Stack

direction="block" is the default for forms, sections, panels, and vertical content rhythm. Use direction="inline" for action rows and other one-line groups. Because these are logical directions, inline flow follows the document direction.

align controls the cross axis; justify controls the main axis. Stack does not add wrapping or responsive breakpoint props in this first contract.

Container

Container sizes are content bounds, not viewport breakpoints: sm 40rem, md 48rem, lg 64rem, xl 80rem, 2xl 96rem, and full without a maximum. The element stays fluid below its maximum width.

Gutters use padding-inline, so left-to-right and right-to-left documents share the same contract. Prefer intrinsic CSS, Grid/Flexbox, and container-aware composition before introducing viewport-specific rules.

Installation and imports

Load the layout stylesheet once for the shared visual contract, then use the framework surface that fits your application.

Styles

import '@vyrnforge/web/styles/layout.css';

Native Web can use the documented data-vf-* hooks directly.

Framework imports

// React
import { Container, Stack } from '@vyrnforge/react/layout';

// Angular
import { VfContainerDirective, VfStackDirective } from '@vyrnforge/angular/layout';

// Vue
import { Container, Stack } from '@vyrnforge/vue/layout';

// Elements
import { defineLayoutElements } from '@vyrnforge/elements/layout';

Accessibility

Layout primitives do not add ARIA roles or interaction behavior. Keep the native element that expresses the content's meaning: use main for the primary page region, nav for navigation, section when it has an accessible heading, and neutral div elements when no semantic role is needed.

React and Vue expose an as option for this reason; Angular decorates the native element you author. With Elements, use Native Web hooks on semantic HTML when native landmark or section semantics matter instead of replacing that element with a neutral custom element.

Styling

The canonical stylesheet lives in @vyrnforge/web, uses low-specificity selectors, and consumes the public --vf-space-* tokens. Application CSS can override the public spacing tokens in a local scope to adapt rhythm without a JavaScript theme or style-prop runtime.

.compact-panel {
  --vf-space-md: 0.75rem;
  --vf-space-lg: 1rem;
}

Use ordinary CSS for layout needs outside these primitives. This release intentionally does not provide arbitrary margin/padding/display props, a 12-column grid abstraction, or viewport breakpoint props.

Framework API

React / Vue

Stack: as, direction, gap, align, justify. Container: as, size, gutter.

Angular

vfStack with vfStackDirection, vfStackGap, vfStackAlign, vfStackJustify; vfContainer with vfContainerSize and vfContainerGutter.

Native Web

Use data-vf-stack / data-vf-container and the documented configuration attributes on your semantic element.

Elements

Call defineLayoutElements() to register <vf-stack> and <vf-container>. Their direction, gap, align, justify, size, and gutter attributes map to the same shared contract.

Compatibility

The exported layout types, documented data attributes, Elements attributes, and public --vf-space-* tokens are compatibility commitments. Private --_vf-* variables and internal wrapper implementation details are not.

Not included yet: Grid, Inline/Cluster, and Box. They remain separate design decisions so this first release does not accidentally turn VyrnForge into a general CSS-prop API.
