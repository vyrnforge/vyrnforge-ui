Build page structure with focused primitives: use Container for content bounds, Stack for block flow, and Cluster for wrapping inline groups.

Start with the browser's layout model.VyrnForge layout primitives add shared spacing and predictable defaults without replacing CSS Grid, Flexbox, container queries, or semantic HTML.

Overview

Each layout primitive owns one job. Container constrains and centers page or section content. Stack creates block-axis rhythm between related siblings. Cluster groups inline content such as actions, tags, and controls and wraps it when space runs out.

Container

Use it around page or section content that needs a maximum inline size and consistent logical gutters.

<main data-vf-container data-vf-container-size="lg">…</main>

Stack

Use it when related siblings should flow vertically with a shared gap instead of individual margins.

<section data-vf-stack data-vf-stack-gap="lg">…</section>

Cluster

Use it when related inline items should stay together and wrap naturally as available space changes.

<div data-vf-cluster data-vf-cluster-gap="sm">…</div>

Quick start

A typical page composes a constrained Container with Stacks for section rhythm and a Cluster for actions. The example keeps the same layout vocabulary across every supported surface.

Spacing

Layout uses one public spacing vocabulary rather than arbitrary pixel props. The scale is available as CSS custom properties and through typed gap/gutter options.

Stack

Stack is deliberately block-flow only. Use it for forms, sections, panels, and vertical content rhythm. align controls the cross axis and justify controls the block-flow main axis.

Stack does not expose a direction switch, wrapping, responsive breakpoint props, or arbitrary style props. Use Cluster for wrapping inline groups and ordinary CSS when the requirement does not match a shared primitive.

Cluster

Cluster lays out children on the inline axis with wrapping enabled. It is intended for action groups, tags, filters, compact tool groups, and similar content where the items should wrap rather than overflow or require viewport breakpoint props.

Inline order follows the document direction, so the same contract works in left-to-right and right-to-left contexts.

Container

Container sizes are content bounds, not viewport breakpoints: sm 40rem, md 48rem, lg 64rem, xl 80rem, 2xl 96rem, and full without a maximum. The element stays fluid below its maximum width.

Gutters use padding-inline, so left-to-right and right-to-left documents share the same contract. Prefer intrinsic CSS, Grid/Flexbox, and container-aware composition before introducing viewport-specific rules.

Installation and imports

Load the layout stylesheet once for the shared visual contract, then use the framework surface that fits your application.

Styles

import '@vyrnforge/web/styles/layout.css';

Native Web can use the documented data-vf-* hooks directly.

Framework imports

// React
import { Cluster, Container, Stack } from '@vyrnforge/react/layout';

// Angular
import { VfClusterDirective, VfContainerDirective, VfStackDirective } from '@vyrnforge/angular/layout';

// Vue
import { Cluster, Container, Stack } from '@vyrnforge/vue/layout';

// Elements
import { defineLayoutElements } from '@vyrnforge/elements/layout';

Accessibility

Layout primitives do not add ARIA roles or interaction behavior. Keep the native element that expresses the content's meaning: use main for the primary page region, nav for navigation, section when it has an accessible heading, and neutral div elements when no semantic role is needed.

React and Vue expose an as option for this reason; Angular decorates the native element you author. With Elements, use Native Web hooks on semantic HTML when native landmark or section semantics matter instead of replacing that element with a neutral custom element.

Styling

The canonical stylesheet lives in @vyrnforge/web, uses low-specificity selectors, and consumes the public --vf-space-* tokens. Application CSS can override public spacing tokens in a local scope to adapt rhythm without a JavaScript theme or style-prop runtime.

Use ordinary CSS for layout needs outside these primitives. VyrnForge does not provide arbitrary margin/padding/display props, a fixed 12-column abstraction, or viewport breakpoint prop objects.

Framework API

React / Vue

Stack: as, gap, align, justify. Cluster: as, gap, align, justify. Container: as, size, gutter.

Angular

vfStack owns block flow; vfCluster owns wrapping inline flow; vfContainer owns content bounds. Each exposes the corresponding typed spacing/alignment options.

Native Web

Use data-vf-stack, data-vf-cluster, or data-vf-container and the documented configuration attributes on your semantic element.

Elements

Call defineLayoutElements() to register <vf-stack>, <vf-cluster>, and <vf-container>. Custom layout elements remain semantically neutral.

Compatibility

The exported layout types, documented data attributes, Elements attributes, and public --vf-space-* tokens are compatibility commitments. The pre-release rebuild intentionally removes the earlier Stack direction option rather than preserving overlapping responsibilities.

Not included yet: Grid and Box. Grid still needs an independently validated intrinsic sizing contract. Box will not be added unless it owns a meaningful cross-framework responsibility beyond exposing generic CSS properties.
