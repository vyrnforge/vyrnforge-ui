RangeSlider chooses a lower and upper bound using two constrained range controls.

Overview

Use RangeSlider when users need to choose an ordered minimum and maximum from the same numeric domain.

Installation and imports

Import from the framework-specific /range-slider subpath and load @vyrnforge/web/styles/range-slider.css.

Quick start

Anatomy

Root, Start input, and End input form the public composition.

State

Lower and upper numeric values are kept ordered and clamped to authored min, max, and step constraints.

Behavior

Updating either thumb preserves the ordering invariant without introducing domain-specific normalization.

Interaction

Each thumb preserves native range keyboard and pointer interaction.

Accessibility

Both range inputs carry distinct Minimum and Maximum accessible names plus native value semantics.

Forms

Consumers own names, submission, required policy, and validation of the represented range.

Styling

Canonical CSS is Web-owned and token driven while preserving focus and forced-colors visibility.

Framework API

Ports expose the same ordered pair contract through idiomatic value APIs.

CSR and SSR

Imports are server safe and initial values render without browser-only dependencies.

Do / Don't

Do use for bounded numeric ranges. Don't encode pricing, dates, filtering services, or other product semantics in the library.

Testing guidance

Test ordering invariants, native keyboard adjustment, bounds, labels, SSR, and axe.

Compatibility

React, Angular, Vue, and Elements implement sibling RangeSlider ports.
