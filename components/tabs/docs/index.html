Tabs presents one active panel from a labeled set while preserving shared semantics, keyboard behavior, focus rules, and state across framework ports.

Overview

Use Tabs when several peer sections share one region and users should switch between them without navigating to a different location. Tabs is a compound component: a root owns selection, a tablist owns directional keyboard navigation, tabs identify selectable sections, and tabpanels contain the corresponding content.

Choose a framework to run the checked-in Tabs example through its public package subpath.

Anatomy and semantics

The tablist uses role="tablist", each tab uses role="tab", and each panel uses role="tabpanel". Tabs expose aria-selected and aria-controls; panels reference their tab with aria-labelledby. Inactive panels are hidden.

Selection and activation

Provide an explicit initial value for server-complete output. Automatic activation is the default: moving keyboard focus also selects the destination tab. Manual activation keeps focus and selection separate until Enter or Space is pressed. Pointer activation selects an enabled tab in either model.

Keyboard interaction

Horizontal tablists use Left and Right Arrow; vertical tablists use Up and Down Arrow. Home moves to the first enabled tab and End to the last. Navigation wraps and skips disabled tabs. Horizontal Left/Right mapping reverses in RTL while logical tab order remains unchanged.

Accessibility

Give every tablist an accessible name using aria-label or aria-labelledby. Disabled tabs remain represented with aria-disabled="true" and are removed from keyboard navigation. Focus indication is independent from selected styling. Shared styles include reduced-motion and forced-colors treatment.

Styling

Stable hooks are data-vf-tabs-root, data-vf-tabs-list, data-vf-tabs-tab, and data-vf-tabs-panel, with state hooks for selection, disabled state, orientation, and activation. Prefer public --vf-* tokens; --_vf-* variables are private.

SSR and hydration

React, Angular, and Vue render roles, selection, roving tabindex, hidden panels, and tab/panel relationships on the server. Use an explicit root id when deterministic consumer-controlled DOM identifiers are important; framework-generated identifiers must remain stable across hydration.

Testing guidance

Query by role and accessible name, then assert selected state and visible panel outcomes. Keyboard tests should verify disabled skipping, wrapping, Home/End, activation mode, orientation, RTL where relevant, and actual browser focus rather than only event callbacks.
