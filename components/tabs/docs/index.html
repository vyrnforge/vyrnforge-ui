Tabs presents one active panel from a labeled set while preserving shared semantics, keyboard behavior, focus rules, and state across framework ports.

Overview

Use Tabs when several peer sections share one region and users should switch between them without navigating to a different location. Tabs is a compound component: a root owns selection, a tablist owns directional keyboard navigation, tabs identify selectable sections, and tabpanels contain the corresponding content.

Quick start

Choose a framework to run the checked-in example through its public package subpath.

Anatomy

A Tabs instance contains a root, one tablist, one or more tabs, and one corresponding tabpanel per tab. The tablist uses role="tablist", tabs use role="tab", and panels use role="tabpanel".

Variants and sizes

Tabs has no visual size variants in the current contract. Behavioral configuration is expressed through orientation and activation mode rather than through visual variants.

State

Selection and keyboard focus are related but distinct state. The selected tab exposes aria-selected="true"; disabled tabs expose aria-disabled="true" and are excluded from roving focus. Inactive panels are hidden. The supplied initial or controlled value must identify an enabled tab in the rendered collection.

Behavior

Automatic activation is the default: moving focus selects the destination tab. Manual activation keeps focus and selection separate until Enter or Space is pressed. Pointer activation selects an enabled tab in either mode. Provide an explicit enabled initial value for server-complete output; framework ports do not infer or rewrite selection by inspecting descendant component trees during server rendering.

Interaction

Horizontal tablists use Left and Right Arrow; vertical tablists use Up and Down Arrow. Home moves to the first enabled tab and End to the last. Navigation wraps and skips disabled tabs. Horizontal Left/Right mapping reverses in RTL while logical tab order remains unchanged.

Accessibility

Give every tablist an accessible name using aria-label or aria-labelledby. Every tab references its panel with aria-controls, and every panel references its tab with aria-labelledby. Focus indication remains distinct from selected styling. Shared styles include reduced-motion and forced-colors treatment.

Forms

Tabs does not participate in form submission and does not define form values, validation, or reset behavior. Place form controls inside tabpanels according to the controls' own contracts.

Styling

Stable hooks are data-vf-tabs-root, data-vf-tabs-list, data-vf-tabs-tab, and data-vf-tabs-panel, with state hooks for selection, disabled state, orientation, and activation. Prefer public --vf-* tokens; --_vf-* variables are private.

CSR and SSR

React, Angular, and Vue render roles, selection, roving tabindex, hidden panels, and tab/panel relationships on the server. Use an explicit root id when deterministic consumer-controlled DOM identifiers are important. Hydration must preserve server state and identifiers without mismatch.

Examples

The basic executable example demonstrates three tabs, a disabled tab, shared styling, and equivalent public concepts in React, Angular, and Vue. Additional examples should be added only when they prove a distinct supported contract such as manual activation or vertical orientation.

Do / Don't

Do use Tabs for peer sections within one context, provide an accessible tablist name, and keep labels concise. Don't use Tabs as application routing, hide required actions behind disabled tabs without explanation, or reproduce keyboard behavior with application-specific handlers.

Testing guidance

Query by role and accessible name, then assert selected state and visible panel outcomes. Keyboard tests should verify disabled skipping, wrapping, Home/End, activation mode, orientation, RTL where relevant, and actual browser focus rather than only event callbacks.

Compatibility

The current interactive ports are React, Angular, and Vue, with canonical styling from @vyrnforge/web. A Web Components Tabs surface is not currently shipped; do not infer one from the existence of the @vyrnforge/elements package.
