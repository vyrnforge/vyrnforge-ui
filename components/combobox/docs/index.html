Combobox combines an editable text field with a filtered listbox while keeping selection, navigation, and application data responsibilities explicit.

Overview

Use Combobox when users benefit from typing to narrow an authored set of available options. The component composes accepted collection-navigation, typeahead, selection, floating-surface, and native input semantics instead of introducing a separate interaction runtime.

Installation and imports

Import Combobox from the framework-specific /combobox subpath and load @vyrnforge/web/styles/combobox.css. Canonical styling remains owned by @vyrnforge/web.

Quick start

Anatomy

Root, editable input, popup content, and options form the public composition. Consumers provide option values, display text, labels, and surrounding field relationships.

State

Open state, input text, and selected value may be framework-idiomatic controlled or uncontrolled state where the port supports both. Product data fetching and persistence remain outside the component.

Behavior

Typing filters or matches authored options, keyboard interaction moves through enabled options, selection updates the chosen value, and dismissal closes the popup without creating a global manager.

Interaction

The editable control remains a native text input. Arrow-key navigation, option selection, Escape dismissal, and focus behavior follow the shared collection and floating-surface contracts.

Accessibility

The input exposes combobox semantics, popup state, autocomplete behavior, and its relationship to the listbox. Options use listbox option semantics, disabled options are excluded from navigation, and consumers remain responsible for an accessible name and any validation descriptions.

Forms

Combobox does not invent form submission or validation policy. Consumers own form names, required state, validation messaging, serialization, and server-side interpretation of the selected value.

Styling

Canonical CSS is Web-owned, token-driven, and shared across ports. Product-specific option rendering and application layout should compose around the public anatomy rather than override interaction behavior.

Framework API

React and Vue expose idiomatic components, Angular exposes standalone directives, and Elements exposes an explicit-registration custom element. All ports implement the same conceptual input/listbox relationship without making one framework the source of truth.

CSR and SSR

Package imports are server safe. Browser-only positioning, focus, and dismissal behavior starts after the rendered elements are available.

Do / Don't

Do use Combobox for editable selection from known options. Don't make the library own remote search services, application routing, permissions, or domain-specific result rendering.

Testing guidance

Test filtering or matching, keyboard opening and navigation, disabled options, selection, popup dismissal, focus behavior, SSR-safe imports, and automated accessibility checks.

Compatibility

React, Angular, Vue, and Elements provide sibling implementations of the shared Combobox concept, with Web-owned canonical CSS and lower-layer interaction capabilities reused where applicable.
