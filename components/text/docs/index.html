Typography gives content hierarchy, rhythm, and emphasis. VyrnForge provides a shared type scale so applications can use consistent visual roles without giving up native HTML semantics.

Choose semantics first.Pick the correct HTML element for meaning, then apply the visual role you want. A visual heading does not automatically become an h1–h6.

Overview

Text provides the display, heading, title, body, label, caption, and overline roles used across VyrnForge. Semantic HTML and visual typography are independent decisions.

VyrnForge typography
One scale. Clear hierarchy.
Use the same typography language for product headings, readable body copy, labels, captions, and dense interface text.
DisplayHeadingTitleBodyLabelCaptionOverline

Use Text when

  • you want reusable visual hierarchy;
  • you want typography to follow public VyrnForge tokens;
  • you need the same role vocabulary across supported frameworks.

Do not use Text to

  • replace semantic heading levels;
  • create form-label relationships;
  • encode disabled, invalid, selected, or other application state.

Installation and imports

Load the public Text stylesheet, then use the Text API for your framework.

Load the styles

import '@vyrnforge/web/styles/text.css';

Native Web can use data-vf-text and data-vf-text-variant directly.

Import Text

// React
import { Text } from '@vyrnforge/react/text';

// Angular
import { VfTextDirective } from '@vyrnforge/angular/text';

// Vue
import { Text } from '@vyrnforge/vue/text';

Elements does not provide a <vf-text> component; use semantic HTML with the Native Web hooks instead.

Quick start

Start with the semantic element your document needs, then choose its visual role.

Anatomy

Typography has two independent choices: what the content means and how it should look.

1

Semantic element

Choose h1–h6, p, label, strong, em, span, or another correct native element.

+
2

Visual role

Apply a role such as heading-lg, body-md, or label-sm. The role changes presentation only.

Same appearance, different meaning is possible.An h2 can use a quieter visual role and a paragraph can use a large display role. Keep document structure semantically correct.

State

Text has no semantic state API of its own. Disabled, invalid, required, selected, pressed, busy, or other state belongs to the owning element or component.

Behavior

Text applies typography without adding document behavior. Display roles are fluid while the rest of the scale resolves from public typography tokens.

Fluid display typography

Display roles use CSS clamp(), so they grow with the viewport while staying within deliberate minimum and maximum sizes.

Resize the browser and this display role adapts.
display-sm → clamp(--vf-font-size-2xl, 1.5rem + 2vw, --vf-font-size-4xl)

Relative units

The public size scale uses rem, keeping browser text-size preferences in the sizing chain.

Interaction

Text adds no pointer, keyboard, focus, selection, or event behavior. If text participates in an interaction, the owning semantic control remains responsible.

Accessibility

Accessible typography starts with semantic structure. Visual hierarchy can reinforce meaning but cannot replace native document semantics.

Preserve heading hierarchy

Choose h1–h6 from the document structure, then choose the visual role independently.

Respect text sizing

Relative units allow browser text-size preferences to continue affecting readable text.

Keep labels semantic

A label-looking span is not a form label. Use a real label and proper control association.

Maintain contrast

If your application changes text or surface colors, keep the resulting contrast readable.

Forms

Text can style form-related copy but does not create form relationships.

Do

<label for="email" data-vf-text data-vf-text-variant="label-md">
  Email address
</label>
<input id="email" type="email" />

Don't

<span data-vf-text data-vf-text-variant="label-md">
  Email address
</span>
<input type="email" />

Styling

Use public CSS custom properties for system-wide typography decisions and the stable variant hook for application-specific roles.

Font families

--vf-font-family-sansAa — Product interface
--vf-font-family-serifAa — Editorial voice
--vf-font-family-monoAa — 0123456789
--vf-font-family-displayAa — Display expression

Use a custom font

@font-face {
  font-family: 'Brand Sans';
  src: url('/fonts/brand-sans.woff2') format('woff2');
  font-display: swap;
}

:root {
  --vf-font-family-sans: 'Brand Sans', system-ui, sans-serif;
  --vf-font-family-display: 'Brand Sans', system-ui, sans-serif;
}

Add or disable a variant

Applications can extend the public TextVariant type through @vyrnforge/web/text.

declare module '@vyrnforge/web/text' {
  interface TextVariantOverrides {
    poster: true;
    heading: false;
  }
}
[data-vf-text][data-vf-text-variant="poster"] {
  font-size: clamp(3rem, 7vw, 6rem);
  font-weight: var(--vf-font-weight-bold);
}

Framework API

The supported surfaces use the same Text variants while letting you choose semantics idiomatically.

Angular<h2 vfText variant="heading-lg">The directive decorates the authored host element.

CSR and SSR

Text has no browser-only behavior. React, Angular, and Vue preserve native semantic elements during SSR; Native Web requires no hydration.

Do / Don't

Do

  • choose semantic HTML before visual treatment;
  • use explicit role names for new work;
  • customize typography through documented public tokens;
  • use TextVariantOverrides for application-specific roles.

Don't

  • treat display-lg as meaning h1;
  • replace semantic form labels with styled spans;
  • depend on undocumented styling selectors;
  • encode component state into typography variant names.

Testing guidance

Test the rendered semantic element, the documented variant API, and application-visible typography behavior when it matters. Avoid depending on undocumented markup or styling details.

Compatibility

The richer role vocabulary is additive: existing body, body-sm, label, title, and heading usages remain supported. See the Compatibility reference for supported runtime and browser ranges.
