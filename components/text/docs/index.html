Text establishes VyrnForge's shared typography vocabulary while preserving native HTML semantics. Styling is opt-in through canonical Web hooks; visual typography does not decide whether content is a heading, paragraph, label, or other semantic element.

Overview

Use Text when content should participate in the VyrnForge typography system. Choose the correct semantic HTML element first, then apply a typography variant. The initial variants are body, body-sm, label, title, and heading.

Installation and imports

Load @vyrnforge/web/styles/text.css for canonical styling. Native Web uses documented data hooks directly. React imports Text from @vyrnforge/react/text, Angular imports VfTextDirective from @vyrnforge/angular/text, and Vue imports Text from @vyrnforge/vue/text.

Quick start

The executable example applies the same typography variants while keeping authored heading, paragraph, span, and section-title semantics intact.

Anatomy

Text has no compound anatomy. The semantic element is the authored native element. VyrnForge contributes data-vf-text, data-vf-text-variant, and the shared token-driven stylesheet.

Variants and sizes

body is the default reading style. body-sm is a smaller supporting style. label is compact and semibold, title is a stronger section-level style, and heading is the largest initial heading treatment. Variant is visual; it never assigns heading level or element semantics.

State

Text has no interactive state. Disabled, invalid, selected, expanded, or loading semantics belong to the component that owns the text. Typography variants must not be used as substitutes for semantic state.

Behavior

Text only applies typography styling. It does not manage events, focus, IDs, relationships, or browser effects.

Interaction

Text provides no pointer or keyboard interaction. Interactive content should use the correct Button, Link, form control, or other semantic control and may consume the same typography tokens through its own canonical stylesheet.

Accessibility

Visual style and document semantics remain independent. A heading-looking treatment on a span does not become a heading, and an h2 remains an h2 regardless of its Text variant. Consumers are responsible for choosing semantic elements that correctly express document structure and labeling relationships.

Forms

Text does not provide form-control semantics. When styling a real form label, retain the native label element and its association with the control; the later Label/Field foundation will own richer form-label contracts.

Styling

The canonical stylesheet is token-driven and low-specificity. The initial public typography scale provides --vf-font-family-sans, font sizes from sm through xl, regular/medium/semibold weights, and tight/compact/normal line heights. Existing control font tokens alias this shared typography foundation rather than maintaining a separate font family.

Framework API

SurfaceText API
Native WebApply data-vf-text and data-vf-text-variant to the correct native element.
ReactText accepts as and variant plus native HTML attributes. as defaults to span.
AngularVfTextDirective uses vfText as the variant input and leaves the authored host element unchanged.
VueText accepts as and variant and forwards ordinary attributes to the rendered native element.
ElementsNo custom element is provided. Native HTML already supplies the correct semantic text elements, so Elements consumers use the Native Web contract.

CSR and SSR

Text has no browser-only runtime. React, Angular, and Vue render native semantic elements on the server; Native Web requires no hydration. The Angular directive only contributes styling attributes to its host element.

Examples

The Quick start example demonstrates heading, body, small body, label, and title variants across Native Web, React, Angular, and Vue without replacing native semantics.

Do / Don't

Do choose semantic HTML first and typography second. Do reuse the shared token scale in future components. Don't use variant="heading" as a substitute for an actual heading element, and don't introduce a custom element solely to style ordinary text.

Testing guidance

Assert the rendered native tag, data-vf-text-variant, SSR output, and computed typography where browser evidence is useful. Avoid coupling tests to private --_vf-* variables.

Compatibility

The initial Text foundation supports Native Web, React, Angular, and Vue. Elements intentionally uses the Native Web contract rather than introducing a wrapper element. Broader release qualification remains governed by VyrnForge's compatibility evidence.
