Use VyrnForge typography to create clear hierarchy while keeping your HTML meaningful. Choose a visual role for the look you need, and keep the semantic element that fits the content.

Semantics and style are separate.Use h1–h6, p, label, and other native elements for meaning. Use a Text variant for appearance.

Overview

Text gives product copy a shared visual language across VyrnForge without replacing native HTML semantics. Use it when you want consistent display, heading, title, body, label, caption, or overline styling.

Quick start

Pick the element first, then choose the typography role. The playground below shows the same Text API across supported frameworks.

Variants and sizes

Choose a role based on the job the text is doing. Display roles are for big moments, headings organize a page, titles name contained content, body roles handle reading, and labels support controls and compact UI.

A useful starting point:Try heading-md for major sections, title-md for cards and panels, body-md for most copy, and label-md for controls.

Semantics and appearance

A typography role never decides what your content means. Keep the document structure correct, then style it to fit the layout.

Section heading

<h2 data-vf-text data-vf-text-variant="heading-lg">
  Billing and plans
</h2>

The h2 carries the document meaning. heading-lg controls its visual treatment.

Prominent paragraph

<p data-vf-text data-vf-text-variant="display-sm">
  Your workspace is ready.
</p>

The text can look large without pretending to be a heading.

For headings, follow the page structure—not the font size.Do not pick h1, h2, or another heading level because of how large you want the text to look.

Native Web and Elements

Use semantic HTML with data-vf-text and data-vf-text-variant. Elements does not add a separate <vf-text> element.

Styling

Start with the public typography tokens when you need to adapt VyrnForge to your brand. That keeps the same type system flowing through every supported surface.

Font families

--vf-font-family-sansAa — Product interface
--vf-font-family-serifAa — Editorial voice
--vf-font-family-monoAa — 0123456789
--vf-font-family-displayAa — Display expression

Use your own font

@font-face {
  font-family: 'Brand Sans';
  src: url('/fonts/brand-sans.woff2') format('woff2');
  font-display: swap;
}

:root {
  --vf-font-family-sans: 'Brand Sans', system-ui, sans-serif;
  --vf-font-family-display: 'Brand Sans', system-ui, sans-serif;
}

Add an application-specific role

If your product needs a role that is not part of the built-in scale, extend the public TextVariant type and provide the matching CSS.

declare module '@vyrnforge/web/text' {
  interface TextVariantOverrides {
    poster: true;
  }
}
[data-vf-text][data-vf-text-variant="poster"] {
  font-size: clamp(3rem, 7vw, 6rem);
  font-weight: var(--vf-font-weight-bold);
}

Accessibility

Most typography accessibility comes from the HTML around the text, not from a visual variant.

  • Keep heading levels in a logical order. Use variants to change appearance without changing that structure.
  • Use a real label for form controls and keep the control association intact. A label-looking span is not a form label.
  • Keep custom sizes relative where practical so browser text-size preferences continue to work.
  • When you customize text or surface colors, maintain readable contrast.

Framework API

Every surface uses the same variant vocabulary. Only the framework-specific way of choosing the native element changes.

SurfaceExampleSemantic element
Native Web<h2 data-vf-text data-vf-text-variant="heading-lg">You author the native element directly.
React<Text as="h2" variant="heading-lg" />as chooses the element; the default is span.
Angular<h2 vfText variant="heading-lg">The directive styles the element you author.
Vue<Text as="h2" variant="heading-lg" />as chooses the rendered native element.
ElementsUse the Native Web hooks.No custom text element is introduced.

Text has no browser-only interaction behavior, so its semantic output remains suitable for server rendering.

Compatibility

Existing body, body-sm, label, title, and heading usages remain supported. Use the Compatibility reference for supported framework and browser ranges.
