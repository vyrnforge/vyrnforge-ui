TagGroup organizes compact authored tags and optional remove actions without owning application data.

Overview

Use TagGroup to present a related collection of compact values, optionally with individual removal controls.

Installation and imports

Import from the framework-specific /tag-group subpath and load @vyrnforge/web/styles/tag-group.css.

Quick start

Anatomy

Root, Item, and optional Remove control form the public composition.

State

The library presents authored tags; the consumer owns the underlying value collection and any removal mutation.

Behavior

Remove controls emit or invoke removal intent without mutating application data independently.

Interaction

Remove controls remain native buttons with normal keyboard activation.

Accessibility

Items use list semantics and remove controls require explicit accessible labels that identify the value being removed.

Forms

TagGroup is not inherently form-associated; consumers own serialization and validation of any represented values.

Styling

Canonical CSS is Web-owned and token driven.

Framework API

Ports expose the same presentational collection/removal contract idiomatically.

CSR and SSR

Imports are server safe and authored tags render without browser-only state.

Do / Don't

Do use for compact value collections. Don't put persistence, domain mutation, or permissions inside the component.

Testing guidance

Test removal callbacks, labels, disabled behavior where applicable, SSR, and axe.

Compatibility

React, Angular, Vue, and Elements implement sibling TagGroup ports.
