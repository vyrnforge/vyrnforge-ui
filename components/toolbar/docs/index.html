Toolbar groups related controls and links into one keyboard-navigable command surface.

Overview

Use Toolbar for a compact set of peer actions whose grouping improves navigation and comprehension.

Installation and imports

Import from the framework-specific /toolbar subpath and load @vyrnforge/web/styles/toolbar.css.

Quick start

Anatomy

Root, Button, Link, and Separator form the public composition.

State

Toolbar itself owns no command state; child controls retain their own pressed, disabled, or navigation state.

Behavior

The root coordinates directional focus among enabled peer items without changing their native activation behavior.

Interaction

Arrow keys follow the configured orientation and Home/End move to the first or last enabled item.

Accessibility

The root exposes toolbar semantics and an authored accessible name while children retain native button/link roles and disabled semantics.

Forms

Toolbar does not own form state; button children default to non-submitting behavior unless explicitly composed otherwise.

Styling

Canonical CSS is Web-owned, token-driven, and preserves visible focus and forced-colors behavior.

Framework API

Ports expose the same orientation and child-item contract idiomatically.

CSR and SSR

Imports are server safe; focus movement is attached only after browser rendering.

Do / Don't

Do use for related peer controls. Don't put routing, command dispatch, permissions, or global shortcut management inside VyrnForge.

Testing guidance

Test horizontal and vertical navigation, Home/End, disabled items, native child activation, SSR, and axe.

Compatibility

React, Angular, Vue, and Elements implement sibling Toolbar ports.
